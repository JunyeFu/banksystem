# 2. 架构决策

## ADR-001：Fineract 是核心账务唯一事实源

事实源范围：

```text
客户核心档案
储蓄账户
贷款账户
核心交易
会计分录
总账余额
业务日期
```

扩展服务禁止直接写：

```text
fineract_default
fineract_tenants
```

扩展系统只能通过 Fineract REST API 或经过确认的官方扩展接口修改核心业务。

## ADR-002：采用模块化单体，而非首期微服务爆炸

首期实现：

```text
bank-channel-service
├─ identity
├─ customer
├─ account
├─ beneficiary
├─ payment
├─ loan-application
├─ risk
├─ notification
├─ document
├─ reconciliation
├─ audit
├─ test-support
└─ fineract-adapter
```

仅将 Mock Clearing 独立部署。

## ADR-003：客户网页不得直接调用 Fineract

正确链路：

```text
Customer Portal
→ Gateway
→ Bank Channel Service
→ Fineract Adapter
→ Fineract API
```

## ADR-004：所有资金写操作必须确定性控制

每个资金写操作必须包含：

- `Idempotency-Key`；
- Correlation ID；
- 状态机；
- 乐观锁；
- Outbox；
- 审计；
- 会计断言；
- 对账；
- 失败补偿；
- 可重放证据。

## ADR-005：可测试性是一等架构能力

关键页面必须包含：

```text
data-page-id
data-page-state
data-testid
aria-label / role / label
稳定 route
加载状态
错误状态
业务状态
```

```java
public enum TransferStatus {
    CREATED,
    VALIDATING,
    RISK_REVIEW,
    PENDING_APPROVAL,
    PENDING_CORE_POSTING,
    PENDING_CLEARING,
    SETTLED,
```

```java
@Component
public final class TransferStateMachine {

    private static final Map<TransferStatus, Set<TransferStatus>> ALLOWED =
        Map.ofEntries(
            Map.entry(TransferStatus.CREATED,
                Set.of(TransferStatus.VALIDATING)),
            Map.entry(TransferStatus.VALIDATING,
                Set.of(TransferStatus.RISK_REVIEW, TransferStatus.FAILED)),
            Map.entry(TransferStatus.RISK_REVIEW,
                Set.of(
                    TransferStatus.PENDING_APPROVAL,
                    TransferStatus.PENDING_CORE_POSTING,
                    TransferStatus.FAILED)),
            Map.entry(TransferStatus.PENDING_APPROVAL,
                Set.of(
                    TransferStatus.PENDING_CORE_POSTING,
                    TransferStatus.FAILED)),
            Map.entry(TransferStatus.PENDING_CORE_POSTING,
                Set.of(
                    TransferStatus.PENDING_CLEARING,
                    TransferStatus.SETTLED,
                    TransferStatus.FAILED)),
            Map.entry(TransferStatus.PENDING_CLEARING,
                Set.of(
                    TransferStatus.SETTLED,
                    TransferStatus.TIMED_OUT,
                    TransferStatus.FAILED)),
            Map.entry(TransferStatus.SETTLED,
                Set.of(
                    TransferStatus.RETURNED,
                    TransferStatus.REVERSAL_PENDING)),
            Map.entry(TransferStatus.REVERSAL_PENDING,
                Set.of(TransferStatus.REVERSED))
        );

    public void check(TransferStatus from, TransferStatus to) {
        if (!ALLOWED.getOrDefault(from, Set.of()).contains(to)) {
            throw new IllegalTransferTransitionException(from, to);
        }
    }
}
```

# 11. Fineract Adapter

```java
@Component
public final class FineractClient {

    private final WebClient client;

    public FineractClient(
            WebClient.Builder builder,
            FineractProperties properties,
            CredentialProvider credentialProvider) {

        this.client = builder
            .baseUrl(properties.baseUrl())
            .defaultHeader(
                "Fineract-Platform-TenantId",
                properties.tenant())
            .filter((request, next) ->
                credentialProvider.authorizationHeader()
                    .flatMap(auth -> next.exchange(
                        ClientRequest.from(request)
                            .header(HttpHeaders.AUTHORIZATION, auth)
                            .build())))
            .build();
    }

    public Mono<FineractTransferResponse> createTransfer(
            FineractTransferRequest request,
            String idempotencyKey,
            String correlationId) {

        return client.post()
            .uri("/accounttransfers")
            .header("Idempotency-Key", idempotencyKey)
            .header("X-Correlation-Id", correlationId)
            .contentType(MediaType.APPLICATION_JSON)
            .bodyValue(request)
            .retrieve()
            .onStatus(HttpStatusCode::isError, FineractErrorMapper::map)
            .bodyToMono(FineractTransferResponse.class);
    }
}
```

注意：

- 精确 API 路径和幂等 Header 以本地 Swagger 为准。
- 资金 POST 不得无条件自动重试。
- 凭据和原始错误不得返回前端。
- 所有调用必须带 Tenant、Request ID 和 Correlation ID。

# 23. 代码规范

## 23.1 Java

- Java 21；
- `record` 用于不可变 DTO；
- 金额使用 `BigDecimal`；
- 禁止 `double` 表示金额；
- Controller 不写业务逻辑；
- Service 不直接拼 SQL；
- 事务边界位于 Application Service；
- 枚举集中定义；
- 异常映射为 Problem Details；
- 所有 public API 有测试。

## 23.2 TypeScript

- `strict: true`；
- 禁止 `any`，例外必须有注释；
- API DTO 由契约生成或集中定义；
- Server State 使用 TanStack Query；
- Zustand 只存 UI 状态；
- 表单使用 React Hook Form + Zod；
- 页面不能直接调用 `fetch`；
- 所有关键交互有测试 ID 和 ARIA。

## 23.3 SQL

- 所有变更通过 Liquibase；
- 表名和列名使用 snake_case；
- 金额 `NUMERIC(19,2)`；
- 时间 `TIMESTAMPTZ`；
- 每张业务表有 `created_at`、`updated_at`；
- 可变业务表有 `version`；
- 重要查询有索引；
- 禁止手工修改生产式 Schema。
