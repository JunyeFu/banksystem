# RAG 知识缺口与后续演进

更新时间：2026-07-15。

## 已完成

- 正式文档、外部资料、任务计划和生成索引已分层。
- 默认检索域排除历史与第三方资料。
- 分块携带来源、SHA-256、状态、权威级、版本、章节、行号和操作标识。
- OpenAPI 按路径、Markdown 按标题层级、源码按逻辑窗口分块。
- 建立权威权重、状态权重、检索配置和黄金问题验证。
- `.env`、密钥、运行数据、日志、Trace、Worker 产物、原始 DOCX/PDF和本地交付件均被排除。

## 仍需演进

1. 当前检索以加权词法召回为主；后续可在黄金问题稳定后增加本地向量召回和确定性重排。
2. 当前源码采用符号提示加重叠窗口；后续可增加 Java/TypeScript AST 解析器。
3. 前端与后端 OpenAPI 尚未完整覆盖全部实现，契约矩阵中的缺口仍需按 B0/B1 前置任务修复。
4. 运行态证据目前来自版本化文件；后续可增加只读运行快照导入，但不得索引凭据或真实数据。
5. 黄金问题应随前端缺陷修复与 Coze/Harness 核心契约增长，并为不允许进入运行时的仓库资料增加负样本。

## 使用边界

RAG 只负责定位依据。当前状态结论必须回到源码、契约、测试或运行证据验证；计划、调研和历史资料不能证明实现完成。
