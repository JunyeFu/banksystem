# 04 测试、上线与验收文书

## 阶段目标

将“能运行”转化为可复核的质量、风险和业务验收证据。测试、投产与验收相互关联，但不得互相替代。

## 最小文书包

| 文书 | 必填内容 | 证据要求 |
|---|---|---|
| 测试策略与计划 | 范围、环境、数据、角色、入口/出口准则、风险、缺陷规则、进度 | 需求追踪矩阵与测试资产版本 |
| 测试用例与数据清单 | 前置条件、步骤、预期结果、业务断言、数据来源/脱敏 | Case ID、Fixture namespace、禁止生产数据 |
| 测试报告 | 覆盖率、执行结果、缺陷、遗留风险、结论、批准建议 | 日志、Trace、截图、接口结果、哈希 |
| UAT 方案与报告 | 业务场景、业务代表、准入/退出、问题及结论 | 业务签字与未解决项清单 |
| 上线申请/投产评审单 | 版本、范围、变更、风险、窗口、实施步骤、回退、值守、批准 | 生产前检查、回退演练、责任电话按受控渠道保存 |
| 上线实施记录 | 实际时间线、执行人、偏差、异常、验证、回退是否触发 | 与变更单、发布版本、监控结果关联 |
| 验收申请与验收报告 | 合同/需求对照、交付清单、测试/UAT结论、培训、遗留项、验收结论 | 甲乙方/责任人签署或等效审批记录 |

## 本项目适配

- 自动化回归只执行批准且独立验证的脚本；模型输出不能直接成为已验证脚本。
- 验收须同时覆盖业务断言、API/权限、审计、证据、恢复和已知风险，不可只截图“页面成功”。
- 上线/回退文书应把 Fineract、渠道服务、前端、数据库迁移和平台 Worker 的顺序与健康检查写清楚。
