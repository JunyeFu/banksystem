# 06 文书格式与 Word/PDF 生成规范

## 调研结论

已找到广东华兴银行公开的 2025 年度报告。该文件适合参考公开银行信息披露文书的目录、重要提示、章节、页码与财务表格层级；并非项目管理模板，且不应复制其名称、Logo、封面、图片、配色或版式。未检索到可公开复用的广东华兴银行项目立项至交付模板，因此本项目使用自有、通用的严肃金融文书样式。

## 设计 Token

| 角色 | 色值 | 使用位置 |
|---|---|---|
| 墨黑 | `#161616` | 正文、封面主标题、页眉 |
| 监管红 | `#A6192E` | 章节号、风险/待决标识、封面细线 |
| 纸白 | `#FFFFFF` | 正文背景、表格正文 |
| 雾灰 | `#F4F4F4` | 表头、元数据底色 |
| 深灰 | `#525252` | 次级说明、页脚 |

## 标准版式

- A4 纵向；页边距上/下 25.4 mm、左/右 31.7 mm；页眉/页脚 12.5 mm。
- 中文正文使用宋体或等价 CJK 正文字体 10.5-12 pt；标题使用黑体/等价无衬线字体；英数使用 Arial/Calibri。
- 首页采用“黑色文书类别 + 深红细线 + 白底标题区 + 深红/黑色几何带”的抽象图案；不使用银行商标、钞票、印章或真实客户图片。
- 页眉显示“项目编号 | 文书类别 | 受控副本”；页脚显示页码和“仅限项目用途”，版本在文档控制表中维护。
- 文档控制表放在封面后：版本、状态、编制、复核、批准、生效日期、关联需求/变更编号。
- 表格仅用于元数据、责任矩阵、追踪矩阵和清单；不得用大表格承载长段落。

## 写作、层级与表格规则

- 本项目文书采用项目文档编号体系：一级至三级标题使用 `1`、`1.1`、`1.1.1`；如属于需要呈报的管理/审批材料，可改用“一、”“（一）”“1.”“（1）”，同一文书不得混用两套体系。
- 正文首行缩进 2 个汉字、回行顶格；正文 10.5–12 pt、1.25–1.5 倍行距、段前 0、段后 6 pt。编号、日期、金额、版本号、需求 ID、接口 ID 与证据 ID 不得拆行；不使用手工换行凑版面。
- 标题采用“项目名称 + 文书类型”，不使用口号化、感叹式或含糊标题。每一段结论均应写清对象、条件、结果、责任人和证据编号。
- 表格仅用于重复且可比较的信息；表头加粗居中，编号/日期/状态居中，描述性内容左对齐，行高自动扩展。不得在单元格中堆砌长段正文。
- 推荐使用“应、必须、不得、已完成、未通过、待整改、附条件通过”等可验证表述，避免“基本完成”“大概可用”“尽快处理”等无法验收的说法。

## 七类文书最低内容与专属表格

| 文书 | 专属表格 | 必须能证明的结论 |
|---|---|---|
| 项目立项报告 | 里程碑/RACI | 为什么立项、由谁负责、何时决策 |
| 需求规格说明书 | 需求追踪矩阵 | 每项需求如何验收与追踪 |
| 系统设计说明书 | 模块/接口矩阵 | 组件、数据、权限与异常如何实现 |
| 测试计划与报告 | 用例-需求追踪矩阵 | 覆盖范围、结果、缺陷与风险 |
| 上线实施与回退方案 | 实施步骤/验证点表 | 如何上线、何时回退、谁批准 |
| 项目验收报告 | 交付物核验表 | 交付物、验收依据与遗留项 |
| 交付与运维移交手册 | 资产移交清单 | 资产位置、接收责任人与运维边界 |

## 生成流交接

数学建模项目已验证的通用路径为“Markdown 源文档 → Pandoc/XeLaTeX 生成 PDF + reference.docx 生成 Word”。银行项目新增 `scripts/documents/build_bank_project_document.py`，使用同一双输出思想但独立于数学论文的字体、公式和页数规则：

1. 选择 `--document-type`（立项、需求、设计、测试、上线、验收、交付）。
2. 提供 `--title`、`--project-code` 和输出目录；脚本只生成占位文书，不接收或读取密钥。
3. 生成 `.docx` 与 `.pdf`；所有正式内容替换占位字段后，必须经业务、技术、风险/合规和验收责任人审批。
4. Word/PDF 文件是交付物；研究 Markdown 是 RAG 源。不要把生成文件直接写入 `rag/`，避免二进制噪声与重复索引。
