# 05 交付、运维与审计文书

## 阶段目标

项目验收不是文书链终点。交付后必须使银行或项目持有人能够独立运行、审计、恢复和有序变更。

## 最小文书包

| 文书 | 必填内容 | 验收要点 |
|---|---|---|
| 交付清单与资产台账 | 源码、构建、镜像、部署包、配置模板、SBOM、文档、许可证、证据 | 版本/哈希/存放位置/责任人一致 |
| 安装部署手册 | 前置条件、步骤、参数模板、健康检查、失败处理、卸载 | 可在隔离目标重复执行 |
| 运维手册/SOP | 启停、监控、告警、备份、巡检、容量、常见故障、升级 | 不含真实凭据；凭据只引用受控保管位置 |
| 应急与恢复预案 | 分级、触发条件、职责、沟通、恢复路径、演练记录 | 至少含恢复验证和复盘 |
| 培训材料与签到/考核 | 受训角色、操作、边界、考核、遗留问题 | 培训并不替代运维移交 |
| 项目总结/复盘 | 目标达成、质量、风险、偏差、成本、改进项 | 可关闭事项与持续跟踪事项分开 |
| 审计归档目录 | 文档基线、审批、变更、测试、发布、验收、证据哈希、保留期 | 可按项目编号和版本检索 |

## 本项目适配

- 交付对象包含银行系统和“衡准”自动化回归测试平台的独立资产；两者使用不同运行账户、数据库、Volume 和审计链。
- 提供可重放的验证记录、Artifact/Evidence 哈希、恢复演练结果和受控下载审计。
- 禁止将 `.env`、API key、Storage State、运行态目录、截图原始敏感数据或缓存纳入交付包/RAG。

## 公开依据

《银行保险机构信息科技外包风险监管办法》要求对外包活动进行持续风险监测、服务评价和应急管理；对重要数据、客户个人信息和敏感信息实施严格控制。<https://www.china-cba.net/Index/show/catid/322/id/41956.html>
