# 02 采购与外包文书

## 阶段目标

在引入供应商、驻场人员、云/软件服务或外部开发测试能力前，形成可审计的准入、尽调、合同、服务水平与退出证据。外包不转移银行的最终责任。

## 最小文书包

| 文书 | 必填内容 | 关键控制 |
|---|---|---|
| 采购需求书/RFP | 项目目标、范围、功能/非功能要求、验收项、交付清单、评分规则、保密条款 | 需求与验收可追溯，避免仅写“满足现行要求” |
| 供应商准入与尽调报告 | 主体资格、能力、财务/信用、同类案例、人员、分包、信息安全、持续经营 | 对关键服务商形成可复核结论 |
| 外包风险评估 | 服务类型、影响业务、数据类型、集中度、地域、退出与替代方案 | 风险责任人与业务/科技共同确认 |
| 合同/SOW/SLA | 范围、里程碑、服务级别、保密、数据处理、审计权、违约、变更、退出、知识产权 | 明确源代码、配置、文档和培训交付权利 |
| 项目实施方案 | 计划、人员、质量、配置、文档、变更、缺陷、培训、上线、故障响应 | 可作为项目周报和验收的基线 |
| 供应商服务评价与退出报告 | SLA、问题、整改、续约/退出决定、资产/数据交还证明 | 结束后可追溯且可切换 |

## 公开交付物参照

重庆农村商业银行公开采购文件要求项目实施方案覆盖咨询/需求、设计、编码调试、业务测试、压力测试、试运行、培训、验收和投产；同时要求质量、配置、文档、变更、问题跟踪及生产一致源代码交付。该公开要求可作为本项目的“交付物完整性”校验项，不作为其模板内容的复制来源。

## 本项目适配

- 演示项目不得把真实账户、生产交易、真实客户信息、密钥或 Storage State 提供给供应商或模型。
- 对外工具/模型若未来接入，必须建立数据最小化、用途限制、审计与停止使用机制；当前仅允许受控 GPT 推理上下文。
- 合同/SOW 中明确 Docker 镜像、部署清单、SBOM、API 契约、测试资产、证据和恢复手册的归属与交付。
