# 大型银行公开页面设计调研与可复用特征

> 状态：设计研究输入，不是品牌复刻规范。
>
> 调研日期：2026-07-14
>
> 适用范围：客户门户、运营控制台、Mifos X、Keycloak、Grafana 的红白黑严肃金融风格升级。

## 1. 调研边界

本调研只分析大型银行公开官网、个人电子银行介绍页和公开登录/安全入口所体现的信息组织规律。不得复制任何银行的商标、名称、业务文案、图片、插画、页面布局、专有图形或受版权保护的视觉资产。

## 3. 跨银行共性特征

### 3.1 信息架构

1. **以客户任务而非技术系统分组**：账户、转账、缴费、贷款、投资、客户服务、安全，而不是 API、数据库或内部模块名称。
2. **登录与业务分离**：登录页集中身份验证、找回/冻结/帮助和安全声明；登录后再进入资产与交易空间。
3. **高频功能优先**：余额、明细、转账、网点/服务查询等放在可快速抵达的位置；低频配置收拢到个人/安全区域。
4. **安全不隐藏**：安全专区、风险提示、密码与登录管理属于正式导航或明确入口，不能只作为底部文字。
5. **客户服务可达**：帮助、业务指南、投诉咨询等为稳定辅助入口；是否加入本项目需遵循 C1 的确认结果。

### 3.2 资金操作与状态呈现

1. 金额、币种、账户掩码、交易时间和业务状态必须具备稳定视觉层级；金额右对齐、状态单独呈现。
2. 转账等高风险操作应把“输入信息”“安全确认”“处理结果”明确分段；具体是否增加验证码、风险确认或审批等待必须以 C2、C3 为准。
3. 成功、处理中、风险复核、失败、退回、冲正等状态不应只靠颜色；必须同时有中文状态文案、图标或位置语义。
4. 结果页必须提供交易标识、核心参考、时间、来源/去向与可追溯入口，避免仅显示“操作成功”。

### 3.3 视觉秩序

1. 正式银行页面通常保持高对比、低装饰、强网格与稳定导航，而不是娱乐化卡片堆叠。
2. 品牌色应集中于当前导航、主操作和风险强调；其余信息以白底、深色文字、灰色边线建立秩序。
3. 表格、描述列表和任务表单优先承载复杂金融信息；客户概览可使用克制的账户摘要卡。
4. 重要动作需有足够留白、明确按钮层级和不可逆风险提示；不能依赖动态特效吸引注意力。

## 4. 对本项目的设计决策

| 研究结论 | 本项目采用方式 | 边界 |
|---|---|---|
| 客户任务分组 | 客户门户使用账户、转账、收款人、贷款、文档、消息、资料、安全等既有路由 | 不新增业务路由；最终导航以 C1 为准 |
| 登录安全并置 | 客户登录页以身份输入、错误提示和既有安全流程为核心 | 不伪造验证码、UKey、OTP 或风控流程；以 C2 为准 |
| 资金动作分段 | 新建转账、结果页、支付监控与审批队列使用“输入—状态—证据”层级 | 不新增确认步骤或状态枚举；C2、C3、C14 确认后再冻结 |
| 安全中心显性化 | 保留既有安全设置、审计、系统健康、风险告警和审批队列的可见性 | 不把安全功能包装成营销内容 |
| 克制的金融视觉 | 采用墨黑、纯白、深红、金属灰及语义状态色 | 不复制调研银行的官方品牌色、Logo、图形或版式 |
| 高密度运营工作区 | 运营、Mifos X、Keycloak、Grafana 采用侧栏 + 表格/详情/时间线 | 具体第三方页面菜单和字段要以运行实例采集结果为准 |

## 5. 禁止直接复用的内容

- 银行名称、Logo、品牌口号、服务电话、产品名称、投诉渠道和安全提示原文；
- 登录页的专有图案、验证码样式、UKey/盾牌视觉资产和导航结构；
- 任何真实客户、账号、交易、告警或生产环境数据；
- 将调研页面中存在的功能自动视为本项目已有功能。

## 6. 进入视觉设计前的证据要求

1. 客户门户：按 C1–C4 确认最终导航与资金/贷款流程。
2. Mifos X、Keycloak、Grafana：运行实例可访问后，采集版本、主题、菜单、路由、角色权限与关键页面截图。
3. 清算、对账、日终、审批、风险：按 C11–C15 确认是否存在额外操作、详情或状态。
4. 仅在确认后，将该系统的“实际页面事实”写入前端视觉升级包；未确认内容维持 `BLOCKED_TBD`。
