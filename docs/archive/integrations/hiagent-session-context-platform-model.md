# HiAgent 会话上下文与项目知识库平台操作模型

> 文档状态：DRAFT_PLATFORM_MODEL；依据 HiAgent 2.5.1 帮助文档建模，尚未在实际 HiAgent 租户逐屏核验。
>
> 目标：让项目资料由知识库检索供给，让长对话由会话上下文服务压缩与回忆；禁止把完整资料或完整历史直接塞进模型窗口。

## 1. 已证实的平台能力与不可假定项

| 项目 | 结论 | 依据 |
| --- | --- | --- |
| 模型窗口 | 可在“模型 > 服务路由”配置输入加输出的总 token 上限，以及最小、默认、最大输出 token。 | `docs/reference/hiagent-2.5.1/2.5.1帮助文档/用户指南/模型管理/服务路由.md` |
| 插件 | 可在“应用 > 插件 > 自定义插件”创建基于已有服务的 API 插件，配置 URL、Header、授权、工具参数，调试并发布。 | `docs/reference/hiagent-2.5.1/2.5.1帮助文档/用户指南/插件.md` |
| 知识库 | 平台 API 覆盖知识库创建、目录、文件、检索与分片。 | `docs/reference/hiagent-2.5.1/2.5.1帮助文档/API & SDK/HiAgent接口列表概览.md` |
| 会话压缩 | 帮助文档没有证实内置自动摘要/压缩；“清除上下文”不能替代记忆。 | `docs/reference/hiagent-2.5.1/2.5.1帮助文档/用户指南/模型管理/大语言模型体验.md` |

以下方案因此将“会话上下文服务”作为本项目自建 API，再以 HiAgent 自定义插件接入。它不是将模型量化任务误用为会话压缩。

## 2. 平台窗口总览

```text
模型 > 服务路由
    bank-session-rag-route
        ↓
应用 > 插件 > 自定义插件
    bank-session-context（调用 session-context-service）
        ↓
知识库（平台 KBS API / 实际实例 UI）
    bank-project-docs、hiagent-reference
        ↓
智能体编排窗口（需以实际实例菜单核验）
    系统提示词 + 知识库 + bank-session-context + bank-session-rag-route
```

## 3. 窗口一：创建长上下文服务路由

进入目标工作空间，依次选择 **模型 > 服务路由 > 创建服务路由**。

| 窗口字段 | 建模值 | 操作原则 |
| --- | --- | --- |
| 路由名称 | `bank-session-rag-route` | 2–63 字符，明确区分普通聊天模型。 |
| 类型 | 大语言模型 | 帮助文档所列的服务路由类型。 |
| 路由模型服务 | 已部署、支持 128K 或 256K 的模型服务，权重 100% | 不在本文假定具体模型名称；以租户已部署服务为准。 |
| Fallback 模型服务 | 同能力的备用长上下文模型 | 没有合格备用模型时留空，不降级到短上下文模型。 |
| 调用方法 | 优先 Responses API；保留 Chat Completions API 兼容性 | 以实际模型服务能力自动勾选结果为准。 |
| 高级能力 | 开启 Function Call | 工具输出会进入模型上下文，Function Call 更节省上下文。 |
| 上下文窗口长度 | `131072`；若选中模型仅支持 64K，则使用其最大值 | 输入和输出共享总额度，不能只看输入容量。 |
| 最大/默认/最小输出 Token | `8192` / `4096` / `1024` | 三个值均必须小于总窗口；最终以模型服务允许范围为准。 |

保存后，在路由列表确认名称、发布状态和备用服务配置。此路由解决“可用容量”，不解决“历史取舍”。

## 4. 窗口二：创建会话上下文插件

进入目标工作空间，依次选择 **应用 > 插件 > 自定义插件 > 创建插件**。

### 4.1 插件基本信息窗口

| 字段 | 建模值 |
| --- | --- |
| 插件名称 | `bank-session-context` |
| 插件工具创建方式 | 基于已有服务创建 |
| 插件描述 | 在每次 Agent 调用前，根据 session、最新问题、项目 RAG 和长期记忆生成受 token 预算约束的 Context Pack；不返回完整聊天记录。 |
| 插件 URL | `https://<internal-session-context-service>` |
| Header 列表 | `Authorization: Bearer <service-token>`；令牌仅保存于 HiAgent 密钥/运行环境，不写入项目文档或提示词。 |
| 授权方式 | 受控可用；仅授予该银行测试智能体。 |

### 4.2 工具配置窗口

创建工具 `build_context_pack`，请求方法为 `POST`，路径为 `/v1/context-packs`。配置以下入参，不增加未定义的业务字段：

| 入参 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | string | 是 | 对话稳定标识；同一用户会话保持不变。 |
| `user_message` | string | 是 | 当前用户原始问题。 |
| `agent_id` | string | 是 | 用于隔离不同 Agent 的记忆和权限。 |
| `context_budget_tokens` | integer | 是 | 建议 `24000`；小于服务路由总窗口。 |
| `project_scope` | string | 否 | 默认 `banksystem`，用于限制 RAG 检索范围。 |

工具输出只允许一个紧凑 JSON 对象，最大建议 35,000 UTF-8 字节，远低于平台工具输出上限：

```json
{
  "context_pack": "供模型直接读取的受控上下文",
  "memory_version": 12,
  "sources": ["docs/architecture/..."],
  "budget_used_tokens": 18340,
  "compression_applied": true
}
```

在插件详情页执行 **Debug 调试**：使用同一 `session_id` 连续发送两轮消息，第二轮必须能取回第一轮的关键决定；随后在详情页右上角选择 **发布**。未发布插件不能被智能体使用。

## 5. 窗口三：建立项目知识库

帮助文档证实了知识库 API 能力，但未给出本帮助包所对应版本的控制台菜单、字段顺序或截图。因此以下是必须在实际实例执行的对象模型；具体按钮名称以租户 UI 或平台 API 文档为准。

建立两个知识库，而不是上传一个 100K 大文件：

| 知识库名称 | 允许导入 | 禁止导入 | 用途 |
| --- | --- | --- | --- |
| `bank-project-docs` | `docs/` 下正式架构、契约、运行手册、设计决策 | `rag/index/`、`node_modules/`、密钥、运行数据、原件 `raw/` | 回答本项目事实与约束。 |
| `hiagent-reference` | `docs/reference/hiagent-2.5.1/` 下提取后的 Markdown | `raw/` 下 Word/PDF 原件、派生 RAG 分片 | 回答 HiAgent 操作与能力边界。 |

导入时为文件或目录附加可检索元数据：`domain`（architecture/contract/runbook/hiagent）、`source_path`、`version`、`security_level`。每次文档变更先重建项目 RAG，再同步更新 HiAgent 知识库，避免知识库与项目事实源漂移。

## 6. 窗口四：智能体编排模型

帮助文档只证实插件可在“编排或工作流”中选用，未提供本部署版本的 Agent 编排页面字段。应在实际实例中将下列模型逐项映射到可见控件，不凭空补造页面：

| 编排项 | 应配置内容 |
| --- | --- |
| 模型/服务路由 | 选择 `bank-session-rag-route`。 |
| 知识库 | 挂载 `bank-project-docs` 与 `hiagent-reference`；仅按问题检索 Top-K，不注入全文。 |
| 插件 | 添加已发布的 `bank-session-context`。 |
| 调用顺序 | 先调用 `build_context_pack`，再把 `context_pack` 与当前问题提交模型；若需要项目资料，再调用知识库检索。 |
| 系统提示词 | 要求模型将 `context_pack` 作为会话记忆，将知识库结果作为可追溯项目资料；冲突时以当前契约、运行证据和正式 docs 为准。 |
| 发布 | 开启 API 配置并渠道发布；Agent API 使用平台生成的 API Key。 |

建议的系统提示词约束：

```text
先使用 session-context 工具建立 Context Pack；不要复述或请求完整历史。
项目事实必须通过已挂载知识库检索并保留 source_path。
Context Pack 与知识库冲突时，以正式 docs、契约、测试和运行证据为准。
不得把密钥、完整原始文档或超过预算的工具输出写回对话。
```

## 7. 会话上下文服务的必备行为

该服务由本项目实现，接口必须执行以下流程：

1. 读取最近 6–12 轮原文。
2. 读取结构化长期记忆：已确认决策、未决事项、实体、任务、证据路径和上次摘要版本。
3. 对当前问题检索相关历史记忆，以及项目 RAG 的少量高相关片段。
4. 若总量超过 `context_budget_tokens`，把最旧且已完成的对话压缩为结构化摘要；绝不压缩掉未决事项、权限边界、金额、版本、接口契约或证据路径。
5. 返回 `Context Pack`，并记录本次引用来源、token 预算和压缩版本，供审计与回归测试。

## 8. 验收操作

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 长会话回忆 | 连续对话超过 20 轮，第 3 轮记录一项业务约束，第 21 轮询问该约束。 | 返回约束及其来源，不要求用户重复。 |
| 知识库检索 | 询问 HiAgent 的服务路由窗口配置。 | 命中 `hiagent-reference`，不注入整份帮助文档。 |
| 大文件保护 | 提交一个远超正常输入的文档问题。 | 仅返回检索片段/摘要；不把全文交给模型或插件。 |
| 工具输出保护 | 让上下文服务模拟超预算历史。 | 返回受预算约束的 `context_pack`，不出现空响应或超大输出。 |
| 隔离 | 以不同 `agent_id` 使用相同 `session_id`。 | 两个 Agent 的长期记忆互不读取。 |

## 9. 上线前待实际核验

- HiAgent 租户的知识库控制台菜单、创建页字段、分片策略与检索参数。
- Agent 编排页中知识库与插件的精确节点/控件名称，以及是否可以强制工具先执行。
- 目标模型实际支持的最大上下文、Responses API 与 Function Call 能力。
- 自定义插件服务的内网地址、认证方式、审计日志和数据保留期。
