## 3.1 Midscene

### 官方来源

```text
https://midscenejs.com/api
https://midscenejs.com/integrate-with-playwright
https://midscenejs.com/model-strategy
https://midscenejs.com/model-config.html
https://midscenejs.com/consume-report-file.html
https://midscenejs.com/data-privacy
```

### 已确认

1. Playwright 集成类名为 `PlaywrightAgent`。
2. 导入路径为：

```ts
import { PlaywrightAgent } from '@midscene/web/playwright';
```

3. 官方环境变量命名为：

```text
MIDSCENE_MODEL_BASE_URL
MIDSCENE_MODEL_API_KEY
MIDSCENE_MODEL_NAME
MIDSCENE_MODEL_FAMILY
```

4. 已确定动作时，官方推荐 Instant Action；`aiAct()` 会执行自动规划。
5. 当前推荐 `aiInput` 签名为 locate-first：

```ts
await agent.aiInput('搜索输入框', {
  value: 'Playwright',
});
```

6. 当前推荐 `aiKeyboardPress` 签名为 locate-first：

```ts
await agent.aiKeyboardPress('搜索输入框', {
  keyName: 'Enter',
});
```

7. 当前推荐 `aiScroll` 签名为：

```ts
await agent.aiScroll('主内容区域', {
  scrollType: 'singleAction',
  direction: 'down',
  distance: 600,
});
```

8. `cache: false` 可以显式关闭缓存。
9. `persistExecutionDump` 可以保留逐次执行数据，但内部必须经版本 Adapter 归一化。
10. Midscene 1.x 的动作定位是纯视觉方向，DOM/ARIA 应由 Playwright 证据采集层独立获取。

### V5.4 采用的正确策略

```text
FullActionPlan 不交给 Midscene 自动规划
ActionWindowController 每次只发一个 AtomicAction
AtomicAction 映射为 Midscene Instant Action
Playwright 执行环境同步采集确定性事实
```

### 被明确禁止的旧写法

```ts
// 禁止：把完整案例交给 aiAct 后要求它严格只做当前动作。
await agent.aiAct(fullRegressionCaseText);
```

原因：`aiAct()` 本身会进行任务拆解和多步执行，无法构成严格的单动作预算。

## 3.1A V5.4 手写设计的官方能力边界

官方 Midscene 文档确认：

1. `agent.ai()`/`aiAct()` 是自动规划，会自行拆解并连续执行步骤。
2. `aiTap`、`aiInput`、`aiScroll`、`aiLocate` 等是 Instant Action，动作确定时更快且更可靠。
3. `aiLocate()` 返回 `rect`、`center` 和 `dpr`；官方明确说明不同模型的 `rect` 可能不是严格元素边界。
4. `PlaywrightAgent` 绑定 Playwright `Page`，Midscene 与 Playwright 可以在同一 Worker 中集成。
5. Midscene 报告和 execution dump 可作为原始证据，但项目必须通过版本 Adapter 转换。

由此核验：

```text
双层摘要
游标滑动窗口
ActionExecutionSlot
ActionExecutionLease
ActionEventStore
```

均不是 Midscene 原生内置能力，而是 V5.4 自行开发的控制层。

高风险策略：

```text
Midscene aiLocate
→ Playwright DOM/ARIA Align
→ Playwright Commit
```

符合 `aiLocate` 的官方返回能力，同时规避直接依赖视觉矩形提交不可逆操作。

### 已确认

1. `BrowserContext` 提供 Cookie、Local Storage、Session Storage 隔离。
2. Playwright Test 默认按测试创建独立 Context。
3. Trace 应在创建或导航 Page 前启动：

```ts
const context = await browser.newContext();
await context.tracing.start({
  screenshots: true,
  snapshots: true,
  sources: true,
});
const page = await context.newPage();
```

4. Page 支持 `request`、`response`、`console`、`dialog`、`popup`、`download` 和 WebSocket 事件。
5. `APIRequestContext` 可用于准备服务端前置状态和查询后置业务状态。
6. 截图基线会受到 OS、浏览器、字体、硬件、Headless 模式和渲染环境影响。
7. 正式 Locator 优先使用用户可感知属性和测试契约。
8. 当前 `@playwright/test` 包导出 `./cli`，V5.4 使用：

```ts
const cliPath = require.resolve('@playwright/test/cli');
```

该命名已由官方 `package.json` 的 `exports` 字段核对。

### V5.4 的隔离要求

```text
Replication Worker 与 Validation Worker 分离
不同进程
不同 BrowserContext
不同 Fixture Namespace
不同 Storage State 文件
不同 Evidence Directory
```

### 正确关闭顺序

```ts
try {
  // execute
} finally {
  await context.tracing.stop({ path: tracePath }).catch(() => undefined);
  await context.close().catch(() => undefined);
  await browser.close().catch(() => undefined);
}
```

实际项目应由生命周期服务集中管理，不允许每个步骤自行关闭浏览器。

## 3.5 Spring Boot 与 Quartz

### 官方来源

```text
https://docs.spring.io/spring-boot/reference/io/quartz.html
https://www.quartz-scheduler.org/documentation/
```

### 已确认

1. Spring Boot 支持 `spring-boot-starter-quartz` 自动配置。
2. JDBC Job Store 可通过 `spring.quartz.job-store-type=jdbc` 使用。
3. 生产环境不应在启动时执行会删除现有表的初始化脚本。
4. Spring Boot 官方示例使用 `QuartzJobBean` setter 注入 Spring Bean 和 JobDataMap 属性。

### V5.4 修正后的 Job

```java
@DisallowConcurrentExecution
public final class RegressionScheduleJob extends QuartzJobBean {

    private RegressionRunCommandService commandService;
    private String scheduleId;

    public void setCommandService(
            RegressionRunCommandService commandService) {
        this.commandService = commandService;
    }

    public void setScheduleId(String scheduleId) {
        this.scheduleId = scheduleId;
    }

    @Override
    protected void executeInternal(JobExecutionContext context)
            throws JobExecutionException {
        commandService.createRunFromSchedule(scheduleId);
    }
}
```

### 为什么不默认构造器注入

Quartz Job 实例化方式不等同于普通 Spring `@Component`。只有项目显式配置能够自动装配 Job 的自定义 `JobFactory` 后，才可以把构造器注入作为默认实现。

### 并发语义

`@DisallowConcurrentExecution` 只保证同一 JobKey 不并发；系统仍需：

```text
数据库唯一约束
幂等键
环境锁
运行状态机
消息 Inbox
```

# 7. 本次代码纠正记录

## FIX-054-001：Midscene 输入参数顺序

旧风险：

```ts
await agent.aiInput(value, target);
```

当前推荐：

```ts
await agent.aiInput(target, { value });
```

## FIX-054-002：Midscene 滚动参数

旧风险：只提供方向字符串，无法表达当前 API 的 `scrollType` 和 `distance`。

当前：

```ts
await agent.aiScroll(target, {
  scrollType: 'singleAction',
  direction: 'down',
  distance: 600,
});
```

## FIX-054-003：Midscene 缓存

脚本生产中的真实复刻默认显式：

```ts
cache: false
```

避免旧定位缓存掩盖页面变化。

## FIX-054-004：Coze 环境变量

旧风险：严格 TypeScript 下 `process.env.*` 是 `string | undefined`。

当前使用：

```ts
function requiredEnv(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing required environment variable: ${name}`);
  return value;
}
```

## FIX-054-005：Coze Tool Output

旧风险：未消费 `submitToolOutputs()` 返回的异步生成器。

当前使用流式提交并消费事件。

## FIX-054-006：Quartz 依赖注入

旧风险：默认假定 Quartz Job 支持 Spring 构造器注入。

当前：

```text
QuartzJobBean + setter 注入
```

构造器注入只有在项目显式提供自定义 `JobFactory` 后才允许。

## FIX-054-007：Cron 方言

旧风险：Coze 与 Quartz 表达式均命名为 `cron`。

当前：

```text
CronDialect
COZE_6_FIELD
QUARTZ
```

## FIX-054-008：独立验证

旧风险：复用 Midscene 已经操作过的页面。

当前强制新 Runner、新 Context、新 Fixture 和新证据目录。

## FIX-054-009：Midscene 与 Playwright 执行主体

旧的模糊表述：

```text
Midscene 执行后记录 Playwright 信息
```

修正：

```text

HIGH
```

不得使用可变对话记忆替代事件事实源。

## FIX-054-013：RAG 边界

RAG 只为 Prompt Harness 提供版本化知识证据，不直接调用 Midscene 或 Playwright。

## FIX-054-014：错误原因

自由文本错误升级为 `FailureExplanation`；机器字段不可由 LLM 修改。


## FIX-054-015：正反向流程命名

旧风险：

```text
把脚本失效后的重新生产称为普通 ReauthoringRequest
```

修正：


## FIX-054-016：失败通知事务边界

旧风险：

```text

```

修正：

```text
Run 终态

+ Incident
```

同事务写入，异步 Worker 可靠投递。

## FIX-054-017：恢复路径数量

旧风险：Agent 自由生成多种建议，可能出现自动修复或忽略失败。

修正为两个固定枚举：

```text
ABANDON_AND_REENTER_SUCCESS_CASE
DESCRIBE_CHANGE_AND_REAUTHOR
```

## FIX-054-018：变化描述作用对象

旧风险：

```text
用户描述变化

```

修正：


```text
PAUSE_ON_TERMINAL_FAILURE_AND_NOTIFY
```

只有新脚本验证成功且用户确认替换后恢复。

```text
AgentPlatformNotificationPort
```
