规范词：

- **MUST / 必须**：不满足即禁止合并或交付。
- **MUST NOT / 禁止**：违反即回滚。
- **SHOULD / 应当**：原则上执行，偏离必须记录 ADR。
- **MAY / 可以**：可选增强。
- **PENDING_ENTERPRISE_VALIDATION**：公开技术上可实现，但仍依赖公司租户、模型或质量平台现场验证。

# 1. 写作前技术调研与验证结论

## 1.1 Midscene 与 Playwright

公开官方文档确认：

1. `@midscene/web` 提供 `PlaywrightAgent`，可直接绑定 Playwright `Page`。
2. Midscene 可作为 Playwright Test Fixture 集成。
3. `aiAct()` 会把自然语言任务规划成多个步骤；因此不适合直接承载本项目的严格单动作窗口。
4. 原子操作 API 已确认存在：`aiTap`、`aiInput`、`aiClearInput`、`aiKeyboardPress`、`aiScroll`、`aiHover`、`aiDoubleClick`、`aiRightClick`、`aiLocate`、`aiWaitFor`。
5. `aiInput` 推荐签名为 `aiInput(locate, { value, ...options })`，旧的 value-first 形式只保留兼容性。
6. `aiLocate` 返回 `rect`、`center`、`dpr`，但官方提醒不同模型的 `rect` 语义可能不同。
7. Midscene 1.x 的 UI 动作和元素定位采用纯视觉路线；DOM 信息需要由 Playwright 或额外页面理解流程采集。
8. Midscene 报告可从 1.7.0 起拆分为 JSON 与截图；解析后的字段可能随版本变化，因此必须经过版本 Adapter。
9. 页面截图会直接发送给所选择的模型服务商，因此数据出域和脱敏必须由项目负责。
10. Chromium 是 Midscene + Playwright 的推荐浏览器，因为部分能力依赖 CDP。

因此 V5.4 冻结：

```text
FullActionPlan 由主控层保存
ActionWindowController 每次只下发一个 AtomicAction
Midscene 只执行 AtomicAction
Playwright 采集 DOM/ARIA/Network/Trace
Midscene Dump 不作为内部永久协议
```

## 1.2 Playwright

公开官方文档确认：

1. BrowserContext 提供隔离的 Cookie、Local Storage、Session Storage 和页面状态。
2. Playwright Locator 带自动等待和重试，官方推荐优先使用用户可感知属性和显式测试契约。
3. 推荐定位方式包括 `getByRole`、`getByLabel`、`getByPlaceholder`、`getByText`、`getByTestId`。
4. Playwright 可监听 Request、Response、WebSocket，并可在点击前创建 `waitForResponse`。
5. 若 Service Worker 使路由或网络事件不可见，可在验证后考虑 `serviceWorkers: 'block'`。
6. Trace 可记录 Before/Action/After DOM Snapshot、Network、Console 和源代码。
7. APIRequestContext 可用于创建前置数据和验证后置状态。
8. `storageState` 可能包含可冒用用户身份的 Cookie 和 Header，必须放入忽略目录并短期保存。
9. Screenshot Baseline 会受到 OS、浏览器、字体、硬件和 Headless 模式影响，必须固定环境。
10. Playwright Test 默认通过独立 Worker 进程运行；失败后会丢弃原 Worker 和浏览器。

因此 V5.4 冻结：

```text
复刻 Worker 与验证 Worker 必须完全隔离
脚本验证默认 retries=0
资金类案例默认 workers=1 或使用环境锁
截图仅作为辅助 Baseline
关键文本、URL、网络、输出和业务状态是强制 Baseline
```

## 1.3 Coze / HiAgent

公开 SDK 与 Coze Studio 源码确认：

1. `@coze/api` 提供 `CozeAPI`。
2. 文件可通过 `client.files.upload({ file })` 上传。
3. 对话可通过 `client.chat.stream()`、`create()`、`createAndPoll()` 发起。
4. 文件消息可使用 `{ type: 'file', file_id: ... }` 与文本共同放入 `additional_messages`。
5. 对话可能进入 `requires_action` 状态，工具输出可通过 `client.chat.submitToolOutputs()` 回传。
6. Coze Studio 源码中存在时间触发、事件触发、`crontab` 和六字段 Cron 校验。
7. HiAgent 论文的核心是用 Subgoal 组织 Working Memory，而不是某个固定企业产品 API。

因此 V5.4 将平台名称严格区分：

```text
HiAgentPattern
指 Goal/Subgoal/WorkingMemory 的层次化 Agent 思路

CozePlatformAdapter
指当前可用于 Agent、文件、Workflow、Tool 和 Trigger 的平台适配器

EnterpriseAgentPlatformAdapter
指公司最终采用的 HiAgent/Coze 企业平台适配器
```

禁止把论文 HiAgent、公司内部 HiAgent 产品和 Coze API 混为同一软件实现。

## 1.4 调度

Coze 开源实现存在六字段 Cron；Quartz 官方则使用六或七字段 Cron，并允许 `?`、`L`、`W`、`#` 等语法。不同实现的 Cron 方言不完全等价。

V5.4 必须显式记录：

```text
cronDialect
COZE_SIX_FIELD
QUARTZ
INTERNAL_NORMALIZED
```

不得只保存一个没有方言信息的 `cron` 字符串。

## 1.5 手写项目设计核验结论

手写设计提出的能力均可以映射到现有技术栈，但必须使用严格工程边界：

| 手写概念 | V5.4 正式名称 | 实现位置 |
|---|---|---|
| 对话式控制任务 | `ConversationTaskControl` | Agent Platform + Authoring Control |
| 回归案例行为清单 | `FullActionPlan` | Prompt Harness 输出 |
| RAG 行为模板 | `ActionListTemplateCatalog` | Knowledge/RAG Layer |
| 每行为风险评级 | `ActionRiskAssessment` | Risk Policy Engine |
| 全局摘要 | `GlobalExecutionSummary` | DualSummaryBuilder |
| 上/正/下窗口 | `ActionWindow` | CursorWindowController |
| 预留执行位 | `ActionExecutionSlot` | Slot Service |
| 一次动作限制 | `ActionExecutionLease` | Lease Service |
| 执行历史记忆 | `ActionEventStore` | Event Sourcing |
| Midscene/Playwright协作记录 | `CollaborativeExecutionEvidence` | Evidence Fusion |
| 返回错误原因 | `FailureExplanation` | Failure Explanation Service |

V5.4 进一步确认：

1. Midscene 官方提供自动规划和 Instant Action 两类 API；本项目使用 Instant Action 承载已确定的原子动作。
2. `aiLocate()` 可以返回视觉位置，但高风险动作仍必须由 Playwright 完成 DOM/ARIA 对齐和最终提交。
3. Midscene `PlaywrightAgent` 绑定单个 Playwright `Page`；因此视觉层和浏览器层可以进程内集成，但必须保持逻辑分层。
4. Playwright Request/Response 事件、Trace DOM Snapshot 和 BrowserContext 隔离可用于构建协作证据和独立验证。
5. “视觉模型 16K”在 V5.4 中是公司部署的 `effectiveContextTokenLimit`，不是对公开 Qwen 系列模型的通用声明。
6. RAG 只提供受版本控制的模板、业务规则和知识证据，不得直接执行浏览器操作。
7. 事件溯源保存动作状态变化；数据库 Projection 仅用于查询和界面展示。

# 2. 产品目标

## 2.1 一句话目标

测试人员把质量检测平台中已经人工验证成功的回归案例发送给 HiAgent/Coze Agent，系统通过 Midscene 纯视觉复刻和 Playwright 事实采集，自动生成并独立验证 Playwright 自动化脚本；验证通过后向测试人员交付脚本，并可挂载为定时回归任务。

## 2.2 核心业务价值

```text
人工成功案例
→ 自动获得可维护的 Playwright 脚本
→ 自动验证脚本是否真的复现成功案例
→ 自动纳入周期性回归
```

主要价值：

- 降低人工编写 UI 自动化脚本的时间。
- 把自然语言、格式化步骤和视频统一转换为自动化资产。
- 用真实页面复刻降低主控 LLM 猜测 Locator、Wait 和输出的风险。
- 将 AI 生成阶段与正式回归执行阶段解耦。
- 保留完整证据、版本、审计和失败分类。

## 2.3 关键成功指标

首期建议目标：

| 指标 | 建议门槛 | 说明 |
|---|---:|---|
| Trace 必填字段完整度 | ≥ 98% | StepTrace 强制字段 |
| TypeScript 首次编译通过率 | ≥ 95% | 生成脚本静态质量 |
| 独立执行首次通过率 | ≥ 80% | 不含人工修复 |
| 人工辅助后通过率 | ≥ 95% | 最多规定修复轮数 |
| 10 次连续运行 Flaky Rate | ≤ 5% | 固定环境与数据 |
| 定时触发成功率 | ≥ 99% | 不包含被测环境不可用 |
| 未授权计划外动作率 | 0 | 强制安全门禁 |
| 正式定时运行调用 LLM 次数 | 0 | 已验证脚本确定性执行 |

复刻成功率必须在至少 30–50 条公司真实案例上统计后冻结，不得使用 PoC 的单案例结果代替生产指标。

## 2.4 手写设计冻结的用户层能力

用户通过 HiAgent/Coze Agent 完成以下操作：

```text
输入自然语言成功回归案例
输入格式化成功回归案例
上传成功案例视频
对案例范围和成功终态进行对话确认
暂停、恢复、取消或查询脚本生产任务
下载已验证 Playwright 脚本
创建每周、每月或指定 Cron 的定时回归任务
查询定时运行结果
获取失败原因和处理建议
```

用户层不得直接接触：

```text
Playwright Shell
浏览器 Storage State
模型 API Key
数据库凭据
完整 Cookie/Authorization
本地 Worker 文件系统
```

主控 LLM 在用户层和工具层之间承担：

```text
需求确认
RAG 检索请求
FullActionPlan 生成
动作风险评级
工具调用编排
脚本生成
错误原因解释
```

## 4.1 包含

```text

质量案例管理和导出
```

## 4.2 不包含

- 真实生产银行交易。

- 让视觉模型读取完整计划、密码、Cookie 或 Storage State。
- 把 Midscene 当前会话成功直接视为生成脚本成功。
- 把视频观察直接视为页面或接口事实。
- 把截图相似度作为唯一成功标准。

# 5. 核心业务用例

## UC-01 自然语言生成脚本

```text
测试人员上传或输入人工成功案例
→ Agent 识别缺失项并确认
→ 生成 FullActionPlan
→ 逐动作视觉复刻
→ 生成和验证脚本
→ 返回下载入口
```

## UC-02 格式化案例生成脚本

输入可能来自 XLS、JSON 或平台导出文件。Source Adapter 转换为 `RegressionCaseSource`，动作顺序和成功标准必须保留。

## UC-03 视频增强脚本生成

视频只生成 `ObservedActionSequence`；随后仍必须在真实页面由 Midscene + Playwright 复刻和采集事实。

## UC-04 人工审核脚本

测试开发人员可在 Review Web 中查看：

```text
原始案例
动作计划
每步截图
Midscene 定位
DOM/ARIA
Locator 候选
Network
生成脚本
静态检查
独立执行结果
Baseline Diff
```

## UC-05 挂载每周或每月回归

只有 `SCRIPT_VALIDATED` 且通过审批的脚本可以创建 Schedule。

## UC-06 定时回归失败并进入反向恢复

```text
定时或周期 RegressionRun 失败
→ RegressionFailureIncident
→ Schedule 自动暂停
→ NotificationOutbox
→ HiAgent/Coze 对话主动提醒
→ 可选系统通知/弹窗
→ WAITING_USER_RECOVERY_DECISION
```

Agent 必须给出且仅给出：

```text
1. 放弃当前失败脚本，重新输入人工成功案例。
2. 描述行为变化，重新视觉复刻并生成脚本。
```

## UC-07 放弃失败脚本并重新输入成功案例

```text
用户选择路径一
→ ScriptArtifact 标记 ABANDONED_AFTER_FAILURE
→ 保留旧证据
→ 用户重新输入成功案例
→ 创建新 RegressionCaseVersion
→ 重新执行 ForwardAuthoringFlow
```

## UC-08 描述变化并重新生产

```text
用户选择路径二
→ BehaviorChangeRequest
→ ChangeImpactAssessment
→ BehaviorPlanPatch
→ FullActionPlanVersion N+1
→ Midscene 全量重新复刻
→ Playwright 新证据
→ 新脚本
→ 独立验证
→ 用户选择输出或重新挂载
```

# 7. 冻结架构决策

## ADR-054-01：脚本生产与正式执行分离

```text
Authoring Plane
允许调用主控 LLM、视觉 LLM 和 Midscene

Execution Plane
只执行已验证 Playwright 脚本，不调用任何 LLM
```

## ADR-054-02：三动作窗口由外部控制器实现

Midscene 不保存完整计划。`ActionWindowController` 负责游标、状态、租约和动作预算。

## ADR-054-03：Midscene 只执行原子动作

默认不使用 `aiAct()` 执行完整流程。复杂动作必须先拆解，无法拆解时进入受限例外流程。

## ADR-054-04：视觉定位与脚本定位分离

```text
视觉复刻定位
Midscene + Visual LLM

最终脚本 Locator
Playwright LocatorCandidate + 稳定性评分
```

最终脚本不得默认保存视觉坐标。

## ADR-054-05：Stable StepTrace 是内部事实协议

Midscene 报告、Playwright Trace 和业务 Assertion 均通过 Adapter 转换成 Stable StepTrace。

## ADR-054-06：独立验证不可复用复刻状态

Replication Worker 与 Validation Worker 不共享：

```text
进程
BrowserContext
Storage State
Fixture Namespace
证据目录
临时文件
```

## ADR-054-07：平台 Adapter 隔离 HiAgent/Coze 差异

核心系统不得直接依赖 Coze 的内部字段。平台调用通过 `EnterpriseAgentPlatformPort`。

## ADR-054-08：Cron 必须记录方言

计划必须包含 `cronDialect` 和 `timezone`。内部调度建议使用 Quartz + JDBC JobStore；Coze Trigger 由 Adapter 映射。

## ADR-054-09：AI 输出永远是候选

只有确定性 Harness 和独立验证可以把状态从 `SCRIPT_CANDIDATE` 更新为 `SCRIPT_VALIDATED`。

## ADR-054-10：证据默认脱敏

完整 Authorization、Cookie、Token、Storage State、密码、真实 PII 不得写入 Relay、LLM Prompt 或通用 Evidence。

---


## ADR-054-11：Prompt Harness 与 RAG 先于 Midscene

原始案例必须先经过：

```text
Source Normalization
→ RAG Retrieval
→ Prompt Harness
→ FullActionPlan
→ Plan Harness
```

禁止把完整案例直接发送给 Midscene `aiAct()`。

## ADR-054-12：上下文控制层是独立逻辑层

`MidsceneContextWindowControlLayer` 位于主控编排层与视觉复刻层之间，包含双层摘要、游标、执行位、租约、风险路由和事件溯源。它不是 Midscene 库的内置能力。

## ADR-054-13：每个 ReplicationRun 只有一个活动执行位

同一复刻任务不得并发执行两个业务动作。`ActionExecutionSlot` 必须通过数据库唯一约束或一致性存储保证唯一性。

## ADR-054-14：风险决定动作执行主体

```text
LOW
→ MIDSCENE_DIRECT

MEDIUM
→ MIDSCENE_DIRECT_WITH_STRICT_VERIFY

HIGH
→ MIDSCENE_LOCATE_PLAYWRIGHT_COMMIT
```

高风险操作禁止由 Midscene 直接提交。

## ADR-054-15：事件溯源是动作状态事实源

`ActionEventStore` 保存不可变动作事件；`ActionWindowProjection`、`ActionSlotProjection` 和 Portal 状态均由事件重建或更新。

## ADR-054-16：脚本事实来自协作证据

脚本生成上下文必须使用：

```text
MidsceneDecisionEvidence
+ PlaywrightExecutionEvidence
+ BusinessAssertionEvidence
```

禁止仅根据 Midscene 报告或视觉坐标生成正式 Locator。

## ADR-054-17：错误原因必须结构化

所有终止状态必须生成 `FailureExplanation`，包含失败阶段、错误码、根因分类、证据引用、是否可重试和建议操作。


## ADR-054-18：正向和反向均为一级业务主线

项目不再把定时失败后的处理视为附属功能。`ForwardAuthoringFlow` 与 `ReverseRecoveryFlow` 必须具有独立状态机、API、数据库、审计和验收。

## ADR-054-19：终态失败必须创建 Incident 并主动通知

`FAILED`、`TIMED_OUT`、`SYSTEM_ERROR`、`BASELINE_MISMATCH` 和 `SECURITY_BLOCKED` 必须创建 `RegressionFailureIncident`。运行结果、Schedule 暂停和 NotificationOutbox 必须在同一事务中提交。

## ADR-054-20：恢复协议只有两条用户路径

```text
ABANDON_AND_REENTER_SUCCESS_CASE
DESCRIBE_CHANGE_AND_REAUTHOR
```

不允许模型、平台或开发人员引入“自动修脚本并继续运行”的隐式第三路径。

## ADR-054-21：路径二修改行为计划而非直接修改脚本

用户描述变化后，主控 LLM 只能生成 `ChangeImpactAssessment` 和 `BehaviorPlanPatch`。Patch 通过 Harness 后创建新的 `FullActionPlanVersion`，随后必须重新 Midscene 复刻和独立 Playwright 验证。

## ADR-054-22：失败 Schedule 默认自动暂停

默认策略：

```text
PAUSE_ON_TERMINAL_FAILURE_AND_NOTIFY
```

新脚本通过验证且用户确认替换前，Schedule 不得继续周期触发。

## ADR-054-23：Agent 对话通知强制，系统通知可插拔

`AGENT_CONVERSATION` 是强制通知语义。系统弹窗、Web Push、企业 IM 和邮件通过 `SystemNotificationPort` 扩展。实际平台 API 由 Adapter 隔离。

## ADR-054-24：通知使用 Outbox 和幂等键

通知不得由 Runner 直接调用 Agent API。必须使用事务 Outbox、Lease、重试、备用渠道和 Dead Letter，并以 `runId + notificationType + userId` 去重。

## ADR-054-25：旧资产不可覆盖

旧脚本、旧计划、旧 Baseline、失败证据和 RecoveryDecision 永久可追踪。恢复只能生成新版本。

# 13. 非功能需求

## 13.1 安全

- Agent 不直接获得 Shell、SQL、任意 HTTP、任意文件系统工具。
- 所有工具调用通过 JSON Schema 和 Allowlist。
- 模型生成代码必须经过 TypeScript、ESLint、AST、Import、URL、Secret、Path 检查。
- Storage State、Cookie 和 Token 不进入源码、日志、Relay 或 Agent Prompt。
- 截图发送视觉模型前必须执行数据分类和脱敏策略。
- Artifact 下载必须鉴权、带审计并支持短期 URL。
- 所有 Hash 使用 SHA-256。

## 13.2 性能

初始目标：

```text
Relay 任务领取延迟 P95 < 5s
普通动作证据写入 P95 < 1s（不含模型调用）
Artifact 元数据查询 P95 < 300ms
Schedule 触发延迟 P95 < 30s
Portal 常用页面首屏 < 3s
```

## 13.3 可用性

- Relay 支持 Idempotency、Lease、Heartbeat、TTL 和 Cancel。
- Worker 崩溃后任务可重新领取，但资金类动作必须检查是否已产生副作用。
- Scheduler 使用 JDBC JobStore 或等价持久化实现。
- Artifact 元数据和文件必须可备份恢复。

## 13.4 可审计性

所有关键事件包含：

```text
actorType
actorId
action
resourceType
resourceId
requestId
correlationId
beforeHash
afterHash
previousRecordHash
recordHash
occurredAt
```


企业平台暂时无法主动推送时，必须至少提供 Agent Notification Inbox 和深链接；不得静默丢失失败事件。



V5.4 额外必须满足：

- RAG 检索结果具有版本、来源和 Hash；
- 每个 AtomicAction 具有风险评级和执行策略；
- 双层摘要与 previous/current/next 窗口真实生效；
- 同一 ReplicationRun 同时只有一个活动 ActionExecutionSlot；
- ActionExecutionLease 只能消费一次；
- 高风险动作使用 Midscene Locate + Playwright Commit；
- 动作状态可以从 ActionEventStore 完整重放；
- Stable StepTrace 使用 Midscene 与 Playwright 协作证据；
- 用户能够获取结构化 FailureExplanation；
- Agent 支持自然语言、格式化案例、视频、定时创建、脚本结果和错误原因六类用户交互。
