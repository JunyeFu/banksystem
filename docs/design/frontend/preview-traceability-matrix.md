# 前端预览图追溯矩阵

两个输入包共包含 191 个唯一物理图片文件：PV-0001 至 PV-0189 为单独图片，最后两个组合图片分别覆盖 PV-0190 至 PV-0197、PV-0198 至 PV-0201，因此逻辑设计状态总数为 201。

| PV 范围 | 设计域 | 主要覆盖 | 实现处理 |
|---|---|---|---|
| PV-0001–PV-0055 | 客户门户基础 | 登录、概览、账户、转账起始状态 | 归并为现有客户路由和共享状态 |
| PV-0056–PV-0105 | 客户业务扩展 | 转账结果、收款人、贷款、文档、消息、资料、安全 | 按业务闭环实现，不创建逐图路由 |
| PV-0106–PV-0145 | 运营控制台 | 仪表盘、支付、审批、风险、清算、对账、日终 | 归并为运营壳层与数据组件 |
| PV-0146–PV-0189 | 衡准平台 | 用例、基线、运行、验证、证据、调度、策略、审计 | 标记为目标设计，按 B1–B7 契约实施 |
| PV-0190–PV-0197 | 系统健康组合图 | 多个健康/告警页面状态 | 一个组合物理文件、八个逻辑状态 |
| PV-0198–PV-0201 | 外部管理组合图 | Mifos X、Keycloak、Grafana 等管理状态 | 一个组合物理文件、四个逻辑状态 |

## 追溯规则

- 预览图是验收参考，不是接口、字段、权限或业务状态的事实源。
- 每个逻辑 PV 状态必须关联到路由、组件状态、接口契约和测试编号。
- 原图片不进入普通文本 RAG；只登记 PV 范围、来源包、SHA-256和逻辑映射。
- 自动视觉基线由固定浏览器环境中的可运行页面生成，不能直接把设计图当作 Playwright 基线。
