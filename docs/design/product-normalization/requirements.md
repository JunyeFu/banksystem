# 产品需求规格与追踪

## PRD基线与角色

本稿是2026-10-08已确认需求的结构化展开，2026-11-06补齐公开调研和验收映射；N01—N12编号、合同源和唯一实施顺序不改变。当前整体NO_GO，不把“需求已明确”写成“产品已验收”。首要价值是减少测试组从业务案例到可靠周期回归的总投入，并提供可直接实机演示的合成银行环境；银行不是上线承载真实存款的生产产品。

| 角色 | 要完成的工作 | 可观察结果 |
|---|---|---|
| 案例执行/维护者 | 描述业务目标、查看候选、执行或选择已验证脚本、处理失败 | 获得符合原预期的结果、业务回读、失败原因与可核查证据 |
| 测试负责人 | 查询周期计划、运行历史和异常，决定人工处理 | 能区分测试失败、业务成功/拒绝/未知，不靠开发者口述判断 |
| 本地维护者 | 配置唯一BYOK、服务/凭据、构建与恢复 | 明确报错、可复现启动与同身份验证；没有密钥进入模型/历史 |
| 演示客户/运营人员 | 在合成银行完成业务与运营查询 | Fineract结果与页面/渠道一致；不是机构用户或真实客户画像 |

双产品可以分别理解：银行提供Gateway→Channel→Fineract的真实业务闭环；CLI Agent负责作者化、冻结、调度、证据与人工接管。Quality只读展示，面试准备站完全外部。简洁对话前端是现有CLI/Controller能力的入口，不建立第二个状态源；展示执行摘要、工具动作和结果证据，不把模型内部推理当业务判据。

## 首版范围与非目标

当前首版必须覆盖既有N01—N12；核心闭环是登录/账户/转账/运营回读与测试作者化/固定回归，贷款、文档、对账等既定正式场景不因聚焦展示而从28项删除。产品组合增量不以“只有我们能生成脚本”宣传，详见[替代研究](research-and-charter.md)。

不交付：真实银行资金/生产合规承诺、任意站点验证码绕过、无人审核自动改产品源码、备用模型/隐藏重试、Flowise运行路径、跨环境未验证的Linux/机构服务器兼容、录制数据冒充真实运行、未测ROI。Mifos原生管理页仅为可选管理员工具，不是默认正式浏览器链路。

## 已确认规则
使用者为测试组；输入真实业务操作目标，从浏览器登录、验证码、导航到填写提交并复核。金额、币种、收款方必须明确；缺关键输入不得动作。测试通过由执行前预期决定，余额不足被正确拒绝可以通过。页面超时但核心成功：业务成功、测试失败、禁止重提并转人工。用户授权本方案实施，不恢复逐任务人工提案门。

| ID | 必须行为 | 实现/证据入口 | 责任任务 |
|---|---|---|---|
| N01 | 合成银行最终转账及运营回读，余额守恒 | Channel/Fineract，B03–B08/B13 | RF063/RF057 |
| N02 | CLI自然语言生成并实际执行浏览器任务 | Controller/MCP/Harness/Worker，A01–A03 | RF057 S2 |
| N03 | 缺金额或收款人时无执行、无资金动作 | Journey作者化及A04证据 | RF063 S4/RF057 S2 |
| N04 | 失败原因、截图、业务状态与人工接管 | Harness incidents/artifacts，A07 | RF057/RF064 S2 |
| N05 | 幂等、结果未知只回读、重启恢复 | Channel操作记录，B05/B06/B14、A05/A06 | RF063/RF057 |

## 正常用例与异常
UC-T01：指定账户/100.00 CNY、无费用及并发外部流水→保存初始余额→登录导航→提交一次→原编号查询→核对交易及双边变化→核对页面→出证据。
UC-T02：余额不足预期拒绝→验证拒绝、付款无扣款、收款无入账→测试通过。
UC-T03：页面超时→查询原操作；成功则保留业务成功和测试失败；未知则保持未完成/接管，不猜失败、不换键重提。

## 输入与状态
正式API字段继续由contracts拥有；不将之前教学JSON作为新接口。凭据引用由执行端解析，普通日志/模型不含密码。Run/Journey、业务关联号、幂等键、核心交易号各有职责。业务状态、测试结论与Agent执行状态分别保存。

UC-A01：执行者输入目标和明确业务参数→配置模型仅作者化→合同校验候选→执行并核验→冻结已验证脚本→以后按固定版本周期执行→失败暂停、保留证据并转人工。没有逐提案人工批准门；缺参数先返回所缺信息，不以默认金额/收款方发起资金动作。

UC-A02：原运行失败→先核业务是否已生效/未知→人工给出定位或断言实现纠正→登记不可变反馈→独立候选复验→通过后才可被后续匹配任务使用。原失败不改写，业务目标/金额/预期不变。验证码不可识别时暂停原任务，请人工在原浏览器处理后继续，不新建资金提交。

### 结论语义

| 事先目标与实际结果 | 业务结论 | 测试结论/动作 |
|---|---|---|
| 正常转账，核心/双边变化/页面都正确 | 成功 | 通过 |
| 预期余额不足，明确拒绝且无资金变化 | 符合拒绝预期 | 通过，而不是按HTTP非2xx一律判错 |
| 页面超时但原编号核心已成功 | 成功 | 页面目标未完成则测试失败，要求人工，不重提 |
| 网络失败，原编号回读仍未知 | 未知 | 未完成/失败接管，不猜失败、不换幂等键重做 |
| A07指定受控断言失败 | 依指定场景记录 | 运行保持真实失败；该场景合同可通过，不豁免后续非预期失败 |

## 验收追踪与当前边界

| 要求 | 正式/补充验证 | 必须观察的反例 | 当前结论边界 |
|---|---|---|---|
| N01 | B03—B08、B13、A02 | 页面成功但核心/余额不符不能通过 | 历史银行证据不等于最终候选 |
| N02 | A01—A03 | 没有真实模型/浏览器不能计LIVE | 已有S5真实只读证据，当前28项仍未完成 |
| N03 | A04 | 缺金额/收款方时无资金动作、无伪造成功 | 只凭模型说“缺输入”不足 |
| N04/N11 | A07及RF064接管/验证码合同与UAT | 缺图/日志或暂停后重建资金Run不能通过 | 机构验证码类型与真实UAT未知 |
| N05 | B05/B06/B14、A05/A06、P03 | 重启/重复命令不能重复记账，A06必须新Run复用原冻结脚本 | 不以原Run回读冒充新执行 |
| N06 | RF064调度合同、100次固定只读补充容量 | 租约失联/失败不得隐藏重排资金任务 | 28项不覆盖全部调度体验，补充验收保留 |
| N07 | RF064反馈合同、保留任务前后对照 | 改业务预期、跨身份/场景经验、未独立复验均拒绝 | 不能把日志保存称为改进有效 |
| N08 | RF057登记/验证/demo verify/Quality集成 | 假PASSED、工件漂移、陈旧身份不签GO | 验证器而非人工JSON给出结论 |
| N09 | P01—P07及既定2小时/100次补充容量 | 失败/超时不从分母删除，资金错账为0 | 阈值是需求，当前不是测量结果 |
| N10 | RF065、候选隔离复现与A08交接 | 秘密/风险未处置、未跑远端CI不可标绿色 | 当前安全/许可/CI总门仍未闭合 |
| N12 | 本目录、documents/catalog.yaml、既有理想/实际模型及来源复核 | 目标图不能冒充实现图，个人自评不能改变工程状态 | 本稿与桌面研究不是业务/机构签收 |

精确场景标题与执行合同由scripts/test/rf057/suite.json拥有，共14银行+7Agent+7性能；本表只做用户需求追踪，不扩/删清单或另设发布算法。最终身份必须同时贯通脚本、构建、模型绑定、运行、工件和验证器。

## 非功能与开放条件
固定只读脚本100次/并发2/60分钟、健康批次99次无需人工、真实Agent并发1/2/4各10次且执行p95≤180秒；这些补充目标需纳入驱动后实测，不替换28项。验证码类型、机构服务器网络策略、真实人力基线仍未知，使用既有合成环境推进不依赖这些输入的功能。

既定查询p95≤1秒、页面READY p95≤3秒、入账p95≤15秒、非预期API错误≤1%，资金不变量100%；队列等待与实际执行分别报告，样本/环境/失败均保留。首次正式验收失败的处理服从当前唯一顺序和场景资金边界，不由本PRD重复授权重做。

开放输入仅包括真实案例样本与人工基线、机构部署网络/权限、验证码类型、本人贡献与三角色UAT/演练事实；它们不重新打开已确认需求，也不能由AI代填。公开研究与后续价值实验详见[立项研究](research-and-charter.md)，缺陷/安全修复继续按现有批次，不为写PRD启动新功能。
