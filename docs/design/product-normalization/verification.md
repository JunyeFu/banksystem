# 测试方案与容量验收

## 验证范围与结果语义

本文把已确认需求映射到实际测试入口，当前整体NO_GO。STATIC检查源码/结构，CONTRACT检查边界与反例，INTEGRATION检查自有真实组件，LIVE_E2E检查真实BYOK、浏览器和银行；人工UAT及正式发布另列。测试专用模型只在CI进程使用，不能用于演示或冒充LIVE。通过条件取决于事前业务目标，不以HTTP状态、页面提示或模型自述单独判定。

## 正式门
RF057 BANK-AGENT-ACCEPTANCE-v1：B01–B14、A01–A07、P01–P07，共28项；历史Full18保留而非当前要求。按最终身份顺序执行，首次非预期确定性失败停止；修复改变身份后从起点重验。测试专用模型仅用于CI合同，真实BYOK与浏览器单列证据。

| 清单 | 真实业务与执行关注点 | 必须留存 |
|---|---|---|
| B01—B03 | 客户/运营PKCE、刷新/退出、账户归属 | 页面与认证结果、核心账户回读 |
| B04—B08 | 黄金转账、重复键、异体同键、余额不足、越权 | 原请求/关联、双边余额及流水、核心交易号或明确拒绝 |
| B09—B12 | 通知、收款人、贷款maker-checker、文档版本并发与下载 | 唯一归属、状态/版本、材料与核心结果 |
| B13—B14 | 三项对账及重启连续性 | 对账依据、历史业务和身份连续性 |
| A01—A03 | 自然语言账户核验、小额转账、真实页面图片补充 | 实际BYOK/浏览器、冻结候选、唯一Journey/Run及业务回读 |
| A04—A06 | 缺资金参数不动作、进程恢复、固定脚本新Run复用 | 无资金动作证明、原任务恢复、版本相等且新Run唯一 |
| A07 | 真实文档状态改变后的指定断言失败 | 原失败Run、限定失败码/步骤、完整工件与Quality同事实 |
| P01—P04 | 混合读、支付、同键并发、同版本文档并发 | 全样本时延/错误、唯一记账或唯一版本成功、资金不变量 |
| P05—P07 | Agent排队、30分钟读持续运行、真实门户READY | 实际排队/执行时间、失败、环境及页面就绪测量 |

精确金额、并发、时长和入口以[suite.json](../../../scripts/test/rf057/suite.json)及既有驱动为准。Business/Agent/Performance等profile经rf057-bank.ps1处理身份、合成样本和清理回执；压力资金场景不能改为原保留账户。EOD恢复用隔离集成环境，不推进演示环境的Fineract业务日期。

报告须从实际运行生产并认证登记，再由Harness验证器核对SQLite、身份与工件。A04不只检查“缺信息”文案，还核没有资金动作；A06不能用原Run回读充当新执行；A07运行保持失败，但其指定受控场景可按合同通过。非预期确定性失败先停止后续正式验收，保留原失败并定位修复；这不是结束工程修复授权，也不是产品内隐藏自动重试。

## 反例
资金重复/未知、异体幂等冲突、越权、错误金额、假PASSED报告、变更工件、陈旧身份、未清理、A04未阻止资金动作、A06用原Run回读冒充新的同脚本运行或引用非A01来源、A07冒用其他失败，都必须被拒绝。被测业务拒绝是否导致测试失败由事先预期决定。

## 性能与容量
既定查询p95≤1秒、页面READY≤3秒、入账≤15秒，非预期API错误≤1%；资金错账/重复入账为0，原资金负载零失败要求保持。固定只读回归100次、并发2、批次≤60分钟（含排队与证据封存），≥99次符合预期且无人工；样本重复不能宣称100个独立业务。
真实Agent只读并发1/2/4各10次，执行p95≤180秒，排队另报；小样本只作试用筛查。保留30分钟银行持续运行，新增2小时只读平台观察。资源、OS、模型、脚本、被测版本、样本数、失败和超时均记录，不能删失败美化时延。

正式P05仍为1/2/4共七个任务，不与各级十次的补充样本混计。2026-11-06新增ReadOnlyCapacity真实依赖驱动，复用A01已验证脚本，运行100次/并发2和30个分级任务，再进行2小时只读生命周期观察；130次均需独立身份与真实Harness计时。失败时排空已接纳任务、停止后续准入，不新增模型探针、服务重启或自动修复。驱动源码通过合同不表示这些负载已经实际执行。

## UAT
测试执行者、负责人、维护者分别完成正常回归、余额不足、页面失败但已入账、定时历史与隔离恢复。独立找到Run/业务/证据，准确解释状态，无需开发者代操作。本人分角色预演不能冒充机构签收。参与者尚未实际验收。

## 人力与改进
对同一组10条代表案例记录手工准备/执行/检查与自动化维护/复核/接管，目标节省≥50%，未测不宣称收益。经验改进使用同类保留任务前后对照，同时验证其他任务不退化；不以保存日志证明自主进化。
