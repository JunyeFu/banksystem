# 1. 手写设计的正式转录

## 1.1 用户层

### Agent 平台层

```text
HiAgent/Coze Agent
├─ 支持对话式控制任务
├─ 接收自然语言回归测试案例
├─ 接收格式化回归测试案例
├─ 接收成功案例视频
├─ 创建周期性或定时回归任务
├─ 返回已验证 Playwright 脚本结果
└─ 返回失败阶段、错误原因和处理建议
```

### 主控 LLM 层

主控模型配置名：

```text
MainTextModelProfile
```

默认演示模型：

```text
DeepSeek V4 Flash
```

正式部署时不得在代码中硬编码模型名，必须通过 `TextModelProfile.modelId` 配置。

主控 LLM 必须：

1. 支持对话式任务控制，包括确认、暂停、恢复、取消、重试、查询状态和定时挂载。
2. 把自然语言、格式化案例或视频观察结果转化为结构化 `FullActionPlan`。
3. 在生成动作计划前调用 Prompt Harness 和 RAG，禁止把原始案例直接交给 Midscene 自行规划完整流程。
4. 按每个动作生成风险评级和执行策略。
5. 接收 Midscene 与 Playwright 协作形成的完整证据，生成 Playwright 脚本。
6. 仅在独立验证和 Baseline 比对通过后向用户交付脚本。
7. 在失败时输出确定性的 `FailureExplanation`，不得只返回模型自由文本。

### RAG 层

RAG 必须根据以下信息检索：

```text
回归案例类型
业务域
目标页面
控件类型
成功终态
风险类型
历史失败模式
已有动作模板
页面动作目录
业务规则
```

RAG 至少提供：

```text
ActionListTemplateCatalog
BusinessRuleCorpus
PageActionCatalog
RiskPolicyCatalog
MidsceneVisualGuidance
PlaywrightLocatorGuidance
FailurePatternCatalog
```

RAG 结果用于辅助主控 LLM 生成 `FullActionPlan`，不直接执行浏览器动作。

## 1.2 Midscene 上下文窗口控制层

正式名称：

```text
MidsceneContextWindowControlLayer
```

该层位于主控编排层与 Midscene 视觉复刻层之间，不属于 Midscene 库本身，也不属于 Playwright 浏览器底座。

组成：

```text
DualSummaryBuilder
CursorWindowController
ActionExecutionSlotService
ActionLeaseService
ActionRiskRouter
ActionEventStore
ActionWindowReducer
ContextBudgetEnforcer
```

核心约束：

```text
视觉模型每次只能看到：
全局任务摘要
上一个动作摘要
当前动作完整定义
下一个动作简要预告
当前页面必要状态
当前截图
本次动作租约
```

视觉模型不得看到：

```text
完整历史动作
完整未来计划
其他回归案例
完整 RAG 文档
Secret
Cookie
Storage State
数据库凭据
```

# 2. 双层摘要

## 2.1 全局任务摘要

正式名称：

```text
GlobalExecutionSummary
```

内容：

```text
业务目标
案例编号
角色
入口页面
成功终态
关键测试数据逻辑引用
全局安全约束
当前业务状态
已完成动作计数
当前风险上下文
```

全局摘要在一次 `ReplicationRun` 内保持稳定，只在业务状态、角色、终态或关键输出发生变化时更新。

## 2.2 局部动作摘要

正式名称：

```text
LocalActionWindowSummary
```

内容：

```text
previous
current
next
lastObservation
currentPageState
currentLease
```

局部摘要每个动作更新一次。

# 3. 游标式滑动窗口

正式组件：

```text
CursorWindowController
```

完整计划保存在 `ActionPlanStore`。控制器持有 `cursor`，每次生成：

```text
actions[cursor - 1]
actions[cursor]
actions[cursor + 1]
```

推进规则：

```text
ACTION_VERIFIED_PASSED
→ cursor + 1

ACTION_FAILED
→ cursor 不变

ACTION_AMBIGUOUS
→ cursor 不变并暂停

LEASE_EXPIRED
→ cursor 不变，重新采集页面状态

重复完成事件
→ 幂等返回既有 StepTrace
```

---

# 4. 动作执行位

手写设计中的“预留执行位”正式命名为：

```text
ActionExecutionSlot
```

每个 `ReplicationRun` 同时最多存在一个活动执行位。

状态机：

```text
EMPTY
→ RESERVED
→ EXECUTING
→ VERIFYING
→ PASSED
→ RELEASED

EXECUTING | VERIFYING
→ FAILED
→ RESET_REQUIRED
→ RESERVED
```

执行位负责：

```text
绑定 current step
防止跳步
防止重复执行
防止同一案例并发执行两个动作
保存动作前页面状态引用
保存租约引用
保存验证状态
```

---

# 5. 动作租约

正式名称：

```text
ActionExecutionLease
```

租约至少包含：

```text
leaseId
replicationRunId
windowId
stepId
allowedExecutionMode
allowedOperation
actionBudget = 1
issuedToWorkerId
issuedAt
expiresAt
status
nonce
```

租约只能消费一次。任何重复消费、跨步骤消费、过期消费必须被拒绝并写入安全审计。

# 6. 每动作风险评级

正式对象：

```text
ActionRiskAssessment
```

风险等级：

```text
LOW
MEDIUM
HIGH
```

默认执行策略：

| 风险 | 执行策略 | Midscene | Playwright |
|---|---|---|---|
| LOW | `MIDSCENE_DIRECT` | 定位并执行 | 同步监听、取证和验证 |
| MEDIUM | `MIDSCENE_DIRECT_WITH_STRICT_VERIFY` | 定位并执行 | 强制网络/DOM/业务验证 |
| HIGH | `MIDSCENE_LOCATE_PLAYWRIGHT_COMMIT` | 只做视觉定位 | DOM 对齐、风险门禁后提交动作 |

典型高风险动作：

```text
确认转账
删除数据
审批通过
冲正
核销
日终
批量提交
权限变更
```

高风险动作禁止调用 `aiTap()` 直接提交。应使用：

```text
Midscene aiLocate
→ Playwright DOM/ARIA 对齐
→ 唯一性校验
→ 风险门禁
→ Playwright click/fill/press
→ 结果验证
```

# 7. Midscene 与 Playwright 的执行边界

## 7.1 低、中风险

```text
Playwright 采集 BeforeEvidence
→ Midscene Instant Action 定位并执行
→ Playwright 采集 AfterEvidence
→ Playwright 验证网络、DOM、页面和业务状态
→ 合并证据
```

## 7.2 高风险

```text
Playwright 采集 BeforeEvidence
→ Midscene aiLocate
→ Playwright 将视觉位置与 DOM/ARIA 对齐
→ ActionRiskGate 审核
→ Playwright 执行实际操作
→ Playwright 采集 AfterEvidence
→ Playwright 验证结果
→ 合并证据
```

## 7.3 正式证据来源

```text
MidsceneDecisionEvidence
+
PlaywrightExecutionEvidence
+
BusinessAssertionEvidence
=
CollaborativeExecutionEvidence
```

最终脚本生成使用 `CollaborativeExecutionEvidence`，不直接依赖 Midscene 内部报告格式。

# 10. V5.2 到 V5.4 的主要变化

| V5.2 | V5.4 |
|---|---|
| 三动作窗口基础控制 | 双层摘要 + 游标 + 执行位 + 租约 + 事件溯源 |
| Plan Harness | Prompt Harness + RAG + Plan Harness |
| 单一 Midscene 原子执行器 | 按风险分流的混合执行器 |
| riskLevel 仅作为字段 | 独立 `ActionRiskAssessment` 和 `ActionRiskRouter` |
| Midscene 执行动作 | 低/中风险执行，高风险仅定位 |
| StepTrace 汇总证据 | `CollaborativeExecutionEvidence` 作为证据源 |
| 失败返回状态 | 标准 `FailureExplanation` |
| 知识库泛化描述 | 七类正式 RAG Catalog |
| ActionExecutionLease | 增加 `ActionExecutionSlot` 与一次性 nonce |
| 状态表为主 | Event Store 为事实源，Projection 为查询模型 |

# 11. 冻结实施结论

V5.4 的核心链路冻结为：

```text
用户输入
→ 对话确认
→ RAG 检索
→ Prompt Harness
→ FullActionPlan
→ 动作风险评级
→ MidsceneContextWindowControlLayer
→ ActionExecutionSlot + Lease
→ 低/中风险 Midscene Direct
   或高风险 Midscene Locate + Playwright Commit
→ Midscene/Playwright 协作证据
→ 事件溯源
→ Stable StepTrace
→ 主控 LLM 生成 Playwright 脚本
→ 独立 Playwright 验证
→ Baseline 比对
→ 脚本交付或定时挂载
```

# 12. V5.4 正反向闭环增量冻结

V5.3 手写设计冻结了：

```text
用户层
RAG + Prompt Harness
FullActionPlan
MidsceneContextWindowControlLayer
风险分流
协作证据
事件溯源
脚本生成和验证
```

V5.4 将项目补全为双向闭环：

```text
正向：
用户输入成功案例
→ PlaywrightScriptPackage
→ 输出或挂载 Schedule

反向：
Scheduled Regression 失败
→ 主动提醒
→ 两路径恢复
→ 新 PlaywrightScriptPackage
→ 输出或重新挂载 Schedule
```

## 12.1 手写设计与反向链的关系

反向路径二不新建一套自动化逻辑，而是重新进入手写设计定义的既有链：

```text
用户自然语言变化描述
→ 主控 LLM 修改行为清单
→ FullActionPlanVersion N+1
→ 双层摘要
→ previous/current/next
→ ActionExecutionSlot
→ ActionExecutionLease
→ Midscene/Playwright 风险分流
→ 协作证据
→ 事件溯源
→ 新脚本
→ 独立验证
```

因此正向和反向共享：

```text
RAG
Prompt Harness
ActionRiskAssessment
MidsceneContextWindowControlLayer
PlaywrightExecutionEvidence
Stable StepTrace
ScriptGenerationContext
Independent Validation
```

## 12.2 新冻结的用户层行为

当定时任务失败时，Agent 必须主动提供：

```text
1. 放弃当前失败脚本，重新输入人工成功案例。
2. 自然语言描述变化，重新生成行为清单并视觉复刻。
```

系统不得把“自动修改正式脚本”作为第三条路径。

## 12.3 新冻结的计划修改边界

路径二只允许修改：

```text
FullActionPlan
BaselineDefinition
Fixture 引用
动作风险评级
```

正式脚本不是用户变化描述的直接修改目标。

## 12.4 新冻结的调度安全策略

```text
Schedule 失败
→ PAUSED_WAITING_USER_RECOVERY
```

在新脚本独立验证成功且用户确认替换前，不得再次周期触发。
