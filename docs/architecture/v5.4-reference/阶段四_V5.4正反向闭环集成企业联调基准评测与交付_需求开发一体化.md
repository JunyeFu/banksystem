
# 2. 端到端用户旅程

## 2.1 自然语言案例

```text
测试人员在 Quality Case Portal 建立并人工执行案例
→ Baseline 审批
→ 导出 RegressionCasePackage
→ 上传到 Agent
→ Agent 确认需求
→ 生成 FullActionPlan
→ Midscene 逐动作视觉复刻
→ Playwright 记录 StepTrace
→ 主控 LLM 生成 PlaywrightScriptPackage
→ 阶段二独立执行
→ Baseline 匹配
→ 人工审批
→ Agent 返回 ScriptArtifact 下载入口
```

## 2.2 视频增强案例

```text
人工成功视频
→ 视频审查和脱敏
→ Agent 上传
→ FFprobe / FFmpeg
→ ObservedActionSequence
→ FullActionPlan
→ 真实页面逐动作复刻
→ 真实 DOM/ARIA/Network 取证
→ 后续同自然语言链
```

## 2.3 定时回归

```text
测试人员确认“每周三 09:00”
→ Agent 创建 Schedule Draft
→ 测试经理审批
→ Schedule ACTIVE
→ Quartz/Agent Trigger 创建 RegressionRunTask
→ Scheduled Regression Worker
→ 新 BrowserContext
→ 运行已验证脚本
→ Baseline Comparator
→ 报告和通知
```

## 2.4 脚本失效

```text
RegressionRun FAILED
→ Failure Classification
→ ReauthoringRequest
→ 人工确认
→ Stage 3 新 AuthoringGoal
→ 新 ScriptArtifact Version
→ 旧版本保留并可追溯
```

---


## 2.5 V5.4 反向失败恢复用户旅程

```text
1. Quartz/Agent Trigger 创建定时 RegressionRun
2. Scheduled Regression Worker 执行 PlaywrightScriptPackage
3. Runner 或 Baseline Comparator 返回终态失败
4. Test Control Service 同事务：
   - 保存 RegressionRun 失败
   - 暂停 Schedule
   - 创建 RegressionFailureIncident
   - 写入 AgentNotificationOutbox
5. FailureNotificationWorker 主动向 HiAgent/Coze 对话投递
6. 可选向系统通知、弹窗或企业 IM 投递
7. Agent 展示两条路径
8A. 路径一：用户重新输入成功案例
8B. 路径二：用户描述变化
9. 新脚本重新 Midscene 复刻和 Playwright 独立验证
10. 用户决定输出、替换原 Schedule 或创建新 Schedule
```

## 2.6 路径一完整集成

```text
Incident
→ RecoveryDecision(ABANDON_AND_REENTER_SUCCESS_CASE)
→ old ScriptArtifact = ABANDONED_AFTER_FAILURE
→ Stage 1 SuccessCaseResubmission
→ Stage 3 ForwardAuthoringFlow
→ Stage 2 Independent Validation
→ User Delivery Decision
```

## 2.7 路径二完整集成

```text
Incident
→ RecoveryDecision(DESCRIBE_CHANGE_AND_REAUTHOR)
→ BehaviorChangeRequest
→ ChangeImpactAssessment
→ BehaviorPlanPatch
→ FullActionPlanVersion N+1
→ MidsceneContextWindowControlLayer
→ Full ReplicationRun
→ New ScriptGenerationContext
→ New PlaywrightScriptPackage
→ Independent Validation
→ User Delivery Decision
```

## 2.8 通知降级原则

```text
Agent Conversation 投递成功
→ 正常等待用户选择

Agent Conversation 暂时失败
→ Agent Notification Inbox
→ 备用系统通知
→ Outbox 重试

全渠道失败
→ Dead Letter
→ 运维 Critical Alert
→ Portal Incident 仍可见
```

通知失败不能导致 Incident 丢失，也不能自动恢复 Schedule。

# 13. Benchmark 设计

## 13.1 样本规模

首轮至少 30–50 条真实案例。建议：

| 类别 | 数量 |
|---|---:|
| 登录和查询 | 5 |
| 普通表单 | 8 |
| 支付/资金写入 | 8 |
| 表格和筛选 | 5 |
| Modal/Drawer | 4 |
| iframe/新标签页 | 4 |
| 文件上传下载 | 3 |
| 长页面/滚动 | 3 |
| 异常和错误终态 | 5 |
| 高 DPI/复杂组件 | 5 |

实际总数可以高于 50。

## 13.2 样本要求

每条案例：

```text
人工已成功
Case Version 固定
Baseline Approved
Fixture 可重复
视频可选
风险已标记
成功终态可机器判断
```

## 13.3 指标定义

### Action First-Pass Success Rate

```text
首次动作成功数 / 总动作数
```

### Replication Success Rate

```text
首次完整复刻成功案例数 / 总案例数
```

### Trace Completeness

```text
已填必填 Trace 字段数 / 应填字段数
```

### Script Compile Pass Rate

```text
首次生成后通过 TypeScript 的脚本数 / 总脚本数
```

### Independent Run Pass Rate

```text
首次生成后独立执行通过数 / 总脚本数
```

### Baseline Match Rate

```text
独立执行且 Required Baseline 全部通过数 / 总脚本数
```

### Flaky Rate

```text
同一脚本相同环境重复运行中结果不一致次数 / 总运行次数
```


### RAG Grounded Plan Rate

```text
具有有效知识证据引用的动作数
÷
全部动作数
```

### Risk Policy Agreement Rate

```text
人工评审同意的风险评级数
÷
全部已评审动作数
```

### Lease Violation Rate

```text
成功执行的非法租约消费次数
÷
全部租约消费尝试
```

目标必须为 `0`。

### Event Replay Consistency

```text
事件重放结果与在线 Projection 一致的 Run 数
÷
全部抽检 Run 数
```

### High-Risk Commit Compliance

```text
使用 Midscene Locate + Playwright Commit 的高风险动作数
÷
全部高风险动作数
```

目标必须为 `100%`。

### Failure Explanation Completeness

```text
完整 FailureExplanation 数
÷
全部失败 Run 数
```

目标必须为 `100%`。


### Authoring Time Saved

```text
(人工平均编写时间 - AI 平均生产时间) / 人工平均编写时间
```

### Failure Notification Latency

```text
notificationDeliveredAt - regressionRunFinishedAt
```

目标：

```text
首次投递尝试 ≤ 5 秒
Agent 对话投递 P95 ≤ 30 秒
```

### Notification Delivery Success Rate

```text
DELIVERED notifications / total failure incidents
```

### Recovery Decision Time

```text
recoveryDecisionAt - notificationDeliveredAt
```

该指标用于理解用户响应效率，不作为模型性能指标。

### Reverse Recovery Success Rate

```text
RESOLVED incidents with validated new script
/
incidents that selected a recovery path
```

### Incident-to-Validated-Script Time

```text
newScriptValidatedAt - incidentCreatedAt
```

### Schedule Auto-Pause Compliance

```text
failed scheduled runs that paused schedule
/
terminal failed scheduled runs
```

目标必须为 100%。

### Path Distribution

```text
ABANDON_AND_REENTER_SUCCESS_CASE count
DESCRIBE_CHANGE_AND_REAUTHOR count
```

### Behavior Plan Patch Validation Rate

```text
validated BehaviorPlanPatch / generated BehaviorPlanPatch
```

### Reverse Replication Success Rate

```text
successful reauthoring ReplicationRun
/
path-two ReplicationRun
```

```text
内存
共享内存
浏览器数
目标环境限流
模型并发
Artifact IO
```

容量模型：

```text

× 1 Active Slot
× 1 Active Lease
```

```text
每个 Worker 同时执行 1 个 Midscene Run
每个 Run 同时执行 1 个 AtomicAction
Event Append p95 < 100ms
Projection Lag p95 < 2s
```

- 主控 LLM 能从 `ScriptGenerationContext` 生成完整 Playwright 脚本包；
- 脚本通过阶段二静态门禁、独立执行和 Baseline 比较；
- Agent 可以交付 Artifact 下载入口，并在人工确认后创建定时计划；
- 周、月、一次性、Cron、时区、Misfire 和禁止重叠全部通过测试；
- 正式 RegressionRun 的 LLM 和 Midscene 调用次数为 0；
- 30–50 条真实案例 Benchmark 达到冻结门槛；
- 安全、审计、性能、故障、备份、恢复和 Runbook 全部通过；
- Release Reviewer、Security Reviewer、Test Manager 和企业环境负责人共同签字。
