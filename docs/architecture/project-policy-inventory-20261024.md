# 项目执行策略排查与简化清单

用户授权排查、展示并取消不必要的项目阻挡。此次是仓库治理规则简化，不是移除工具安全控制或银行完整性约束；沿用唯一实施顺序和RF068-S5的治理补充项，不创建并行路线图。

## 上次托管启动拒绝的实际来源

后续状态：用户重新明确冻结/重验指令后，原托管入口已获准并成功执行，未改全局配置/工具规则或换渠道绕过。新身份LIVE随后发现Worker语义误拒，详见[实机根因](refactoring/batches/RF-068/S5-live-root-cause-20261024-02.md)。本节记录前次拒绝事实，不表示该命令永久不可执行；具体拒绝规则仍未披露。

上次命令在exec_command创建执行进程之前返回`Rejected: blocked by policy`，没有运行Node启动辅助，也没有产生项目的RF068_*或AGENT_*错误回执。因此不能将本次拒绝归因于项目ReleaseIdentity、活跃任务检查或进程归属检查。

| 层/来源 | 实际观察 | 判断及处置 |
| --- | --- | --- |
| 工具执行层 | 返回blocked by policy，未提供命中规则或更细原因 | 实际阻挡点；当前不可定位具体宿主规则。项目文件不能取消该拒绝，不改工具规则或换渠道绕过 |
| 本机Codex配置 | config.toml记录danger-full-access、approval_policy=on-request | 这是磁盘配置，不等于当前会话/宿主实际策略；不能断言on-request导致此次拒绝。本轮不改机器全局配置 |
| 本机default.rules | 仅两条Python命令allow规则，没有deny/forbidden规则 | 未发现可删除的本地拒绝条目；不通过添加宽泛allow规避工具拒绝 |
| 项目托管辅助 | 有身份、活跃任务、备份及自有进程检查 | 上次命令未进入该层；它们不是已证实的拒绝源 |

上述配置排查只读取策略字段与规则，不采集账号、模型密钥或配置中的其他私密项。工具未披露的规则保持未知，不猜测具体安全分类。
