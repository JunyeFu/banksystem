# V5.4 Coze/Harness 演示系统与内网迁移基线

> 状态：文档与规划基线；不代表 v5.4 AI 测试平台已经在本仓库实现或完成企业联调。
> 更新：2026-07-14
> 最新职责边界：[`overview/coze-harness-midscene-observability-boundary.md`](overview/coze-harness-midscene-observability-boundary.md)。该文件覆盖本文中与 Codex/GPT 运行时作者化、衡准可写控制面或外部 Agent 禁用有关的旧解释。

## 1. 项目定位

本项目建设的是由 Coze 自定义 Agent 编排、Harness 在本机受控执行的完整演示系统，包含两部分：

1. 基于开源 Fineract/Mifos X 的完整数字银行目标系统；
2. 面向该目标系统的自动化回归测试体系：Coze Agent/Workflow、Harness、Midscene 视觉操作 Agent、Playwright 确定性验证和正式回归，以及只读的衡准指标观测平台。

Coze/Harness 演示版不是降级版。它使用虚构或脱敏数据，不接入真实生产资金或监管系统；Coze 是唯一业务 Agent 编排入口，Harness 是工具、安全和执行层，Midscene 是接入视觉/多模态模型的视觉操作 Agent，衡准只读取观测投影。Codex 只负责项目开发。所有浏览器、Worker、证据和实际执行动作均在本机完成；模型仅接收经过批准的最小化上下文，且不得直接获得被测系统凭据或任意执行能力。

Harness 的独立 SQLite `regression_platform` 数据库是回归测试领域唯一事实来源。它是本机受管运行态，采用 WAL、外键、单写入队列、备份和完整性校验，且不入库。Coze只保存 Agent 配置、会话和 Workflow 编排状态；衡准只读取 Harness 查询模型或观测投影。任何跨系统传递的案例、计划、脚本、基线、运行、事故和修复对象都必须携带权威 ID 与版本，禁止双写形成第二事实源。此 SQLite 决定不替换既有 Fineract/Mifos 和银行渠道 PostgreSQL 核心依赖。

Coze Knowledge Base 是交付系统的唯一运行时知识权威。仓库 `docs/` 与 `rag/` 只用于项目开发、审计和 Codex维护，不被运行中的 Coze、Harness、Midscene或衡准读取、同步或回退。

## 2. 双系统边界

```text
回归测试平台
  -> Customer Portal / Operations Console / Mifos X 等被测网页
  -> Gateway / Bank Channel Service
  -> Fineract API
  -> Fineract 核心账务
```

Fineract 仍是银行核心账务唯一事实源。回归平台可以观察、编排和验证，但不能绕过 Bank Channel Service、直接写 Fineract 数据库或把 AI 输出当作账务事实。

## 3. v4 银行基线与 v5.4 测试平台关系

V4 的落地要求已叠加 v5.4 兼容基线：V4 必须交付可人工重复、可重置、可观察、可比较和可审计的业务流程，不能先完成一个无法被回归平台稳定消费的银行系统，再通过旁路脚本补适配。详细映射见 [`docs/architecture/v4-v54-compatibility-baseline.md`](v4-v54-compatibility-baseline.md)。

| 层 | 当前依据 | v5.4 目标状态 |
|---|---|---|
| 银行核心 | v4 Fineract/Mifos、渠道服务、资金安全规则 | 保持不变，作为外网演示目标系统与内网迁移基线 |
| 测试目标与案例 | 当前 `contracts/`、`scripts/test/`、阶段报告 | 统一为 RegressionCase、Fixture、Baseline、人工成功事实 |
| Coze Agent 编排 | 当前主要为历史规划，尚无本仓库完整运行链 | Coze 负责三类输入、知识、计划、对话控制和恢复编排 |
| Harness 与浏览器自动化 | 当前已有契约、前端与局部测试资产 | Harness 控制三动作窗口；Midscene 视觉 Agent + Playwright 事实采集与独立 Runner |
| 衡准 | 实施暂缓 | 恢复后仅提供只读指标、运行、失败、修复与证据观测，不承担 Agent 支持或写控制 |
| 交付与恢复 | 当前银行系统审计/恢复能力 | 脚本资产、定时回归、FailureIncident、两条 RecoveryOption 与通知闭环 |

## 4. 状态口径

- 银行核心当前状态继续以 `AGENTS.md`、审查报告、测试和运行证据为准；S7 未通过不因 v5.4 文档复制而改变。
- v5.4 的演示结果只能标记为本机验证；Coze 编排、Harness 工具链、Midscene 模型调用和 Playwright 独立验证都必须形成现场证据。尚未完成的 Agent、模型、认证和网络适配标记为 `PENDING_ENTERPRISE_VALIDATION`，不得写成已完成。
- 非编程文档可以描述目标、契约和验收方式，但不得把目标架构伪装成当前实现。

## 5. Coze/Harness 演示与内网迁移门槛

Coze/Harness 演示必须使用虚构/脱敏数据、显式环境隔离、最小权限、不可变镜像、无密钥入库、审计和回归证据。外部模型只能接收经批准的最小化文本或脱敏截图。评审通过后迁移只替换：

- Coze Agent/Workflow 适配与认证；
- 主控和 Midscene 视觉模型 Endpoint、模型 ID 和认证；
- 质量平台导入导出适配；
- 企业身份、通知和网络策略；
- 运行环境与凭据注入。

不得通过迁移删除资金安全门禁、独立脚本验证、Baseline、审计、失败解释或恢复流程。
