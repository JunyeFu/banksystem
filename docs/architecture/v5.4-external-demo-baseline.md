# V5.4 Codex/GPT 演示系统与内网迁移基线

> 状态：文档与规划基线；不代表 v5.4 AI 测试平台已经在本仓库实现或完成企业联调。
> 更新：2026-07-14
> 历史参考：`docs/archive/architecture/v5.4-reference/` 仅保留调研与冻结证据，不再作为实施工作流依据。

## 1. 项目定位

本项目建设的是由 Codex 受控开发与作者化、完全在本机执行的完整演示系统，包含两部分：

1. 基于开源 Fineract/Mifos X 的完整数字银行目标系统；
2. 面向该目标系统的完整回归测试平台：案例输入、人工成功 Baseline、本地 RAG、Codex/GPT 作者化、本地 Plan Harness、Midscene/Playwright 浏览器自动化、脚本生成、独立验证、定时回归、失败事件、反向恢复、证据、审计和交付。

Codex/GPT 演示版不是降级版。它使用虚构或脱敏数据，不接入真实生产资金、监管系统、公司内网、外部编程工作流或第三方 Agent 控制面；所有容器、浏览器、Worker、证据和恢复动作均在本机完成。GPT LLM 仅接收最小化、脱敏推理上下文，且不得直接调用被测系统或执行工具。通过评审后，保持业务与测试契约不变，再按独立项目接入企业平台、模型、质量平台和认证适配器。

## 2. 双系统边界

```text
回归测试平台
  -> Customer Portal / Operations Console / Mifos X 等被测网页
  -> Gateway / Bank Channel Service
  -> Fineract API
  -> Fineract 核心账务
```

Fineract 仍是银行核心账务唯一事实源。回归平台可以观察、编排和验证，但不能绕过 Bank Channel Service、直接写 Fineract 数据库或把 AI 输出当作账务事实。

## 3. v4 银行基线与 v5.4 测试平台关系

V4 的落地要求已叠加 v5.4 兼容基线：V4 必须交付可人工重复、可重置、可观察、可比较和可审计的业务流程，不能先完成一个无法被回归平台稳定消费的银行系统，再通过旁路脚本补适配。详细映射见 [`docs/architecture/v4-v54-compatibility-baseline.md`](v4-v54-compatibility-baseline.md)。

| 层 | 当前依据 | v5.4 目标状态 |
|---|---|---|
| 银行核心 | v4 Fineract/Mifos、渠道服务、资金安全规则 | 保持不变，作为外网演示目标系统与内网迁移基线 |
| 测试目标与案例 | 当前 `contracts/`、`scripts/test/`、阶段报告 | 统一为 RegressionCase、Fixture、Baseline、人工成功事实 |
| Codex/GPT 作者控制 | 当前主要为规划与 PoC 资产，尚非完整运行链 | Codex + 本地 RAG + 确定性 Plan Harness；GPT LLM 仅处理脱敏推理 |
| 浏览器自动化 | 当前已有前端与局部测试资产 | Midscene 原子动作 + Playwright 事实采集与独立 Runner |
| 交付与恢复 | 当前银行系统审计/恢复能力 | 脚本资产、定时回归、FailureIncident、两条 RecoveryOption 与通知闭环 |

## 4. 状态口径

- 银行核心当前状态继续以 `AGENTS.md`、审查报告、测试和运行证据为准；S7 未通过不因 v5.4 文档复制而改变。
- v5.4 的演示结果只能标记为本机验证；Codex/GPT 作者化链必须通过本机控制面、脱敏与最小 Smoke 验证。其他外部 Agent 平台、真实质量平台、企业认证和内网迁移均不属于本机演示，并标记为 `PENDING_ENTERPRISE_VALIDATION`，不得写成已完成。
- 非编程文档可以描述目标、契约和验收方式，但不得把目标架构伪装成当前实现。

## 5. Codex/GPT 演示与内网迁移门槛

Codex/GPT 演示必须使用虚构/脱敏数据、显式环境隔离、最小权限、不可变镜像、无密钥入库、审计和回归证据。除 GPT LLM 的最小化、脱敏推理调用外，禁止任何外网运行时依赖。评审通过后迁移只替换：

- GPT Authoring Adapter 的企业替代适配器；
- GPT 模型 Endpoint、模型 ID 和认证；
- 质量平台导入导出适配；
- 企业身份、通知和网络策略；
- 运行环境与凭据注入。

不得通过迁移删除资金安全门禁、独立脚本验证、Baseline、审计、失败解释或恢复流程。
