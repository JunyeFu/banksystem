# RF066-S2：生产服务、模型与浏览器接线

## 业务目标

浏览器使用CLI同一个真实Agent；模型本地配置，任务绑定不可变，历史和实际执行一致。工作量1–3天，状态只查BANKSYSTEM-RF066-S2-SERVICE-001。

## 输入与输出

输入：RF067的持久化/MCP、RF066-S1的1.0合同与生产行为刻画、当前唯一环境模型。输出：可组合的真实workbench应用、DPAPI密钥保存、同源本地服务和隔离端到端证明；浏览器不持有内部token。

会话续接规则：同conversation有NEEDS_INPUT时，新消息补原任务，只输入当前必要事实；正在运行则409，不暗建并发队列；完成后的新目标可开启新Journey。部分目标缺站点/凭据引用等启动信息时明确索取，不以现有解析器抛错结束整个对话；银行账号密码仍走已有登记流程，不进入模型。不会以“下一任务模型”覆盖待输入任务模型。

## 输入与输出合同细化

以下加法合同已随本包实现为OpenAPI1.1；S1的1.0历史证据保留。实际producer、生成物、消费验证及receipt的结果见本批证据索引，不以只改YAML代替接线：

- 现有bootstrap增加安全blockingReasons，turn增加受限result（回复或测试；NOT_RUN/PASSED/FAILED/UNKNOWN）及续接关联。PASSED只能来源于已有evidenceVerify；Controller回答完不能生成测试通过。
- POST /api/agent/v1/attachments：受控单图二进制，复用已有Harness importer/内容摘要/文件名合同，返回安全attachmentRef及必要名称元数据；不接收服务端路径。当前start只消费第一张，不扩展视频/PDF或多图。
- 消息提交携带单图receipt的attachmentMetadata（attachmentRef、originalFilename），与引用一起进入原请求快照；澄清启动信息时保留，不重命名JPEG为PNG。
- GET /api/agent/v1/turns/{turnId}/evidence：复用production-service.evidence及授权归属检查；GET同turn的artifacts/{artifactId}通过既有artifact_download_grant与受控代理提供允许的工件。浏览器不取得service token、裸文件路径或内部下载授权令牌；不是新增证据库。
- 相同submissionId/同内容返回原turn；不同内容409。网络结果未知和中断先只读查询，不暗换id重试。

允许路径：agent-cli/**、controller/src/**、controller/test/**、scripts/verification/**（均位于platform/hengzhun-regression-system），contracts/openapi/agent-workbench-api.yaml、scripts/test/verify-agent-workbench.ps1、scripts/demo/**和本批文档。禁止本包改Harness/MCP生产语义或前端；必要的下载授权/元数据producer缺口由RF067本包已有合同范围补齐后再回接，不另建顺序或兼容壳。

## 项目易错点

2026-10-21消费接线复审补项（仅BE-C06）：RF068既定入口/agent/与agent.html实际产物不能被当前静态路由正确提供。此项归RF066，白名单仅agent-cli/src/workbench-server.mjs及agent-cli/test/workbench-server.test.mjs。静态路由明确接受/agent/与其assets、无扩展深链接，并返回agent.html；拒绝其他磁盘文件，API/CSP/认证保持。增加/agent/assets与深链接、伪造Host和文件越界回归后再回接S1；不操作生产服务、库、模型或银行。

现有HTTP router只有注入接口，未绑定createProductionService或监听端口。direct start不会把全部执行引用直接当浏览器历史；需从权威结果投影。API CSP不能照搬给页面。保存新profile可能使当前授权不匹配，必须显示真实NOT_READY而非绕过。模型列表/错误不包含原始provider响应。
