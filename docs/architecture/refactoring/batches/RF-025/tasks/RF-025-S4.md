# RF-025-S4 Cold Rollback Task

Execute the disabled Flowise cold path only under a separate exact authorization. Business rule: rollback evidence proves recovery, not normal CLI acceptance. Common failures: sharing a start switch, reusing normal evidence, killing an unknown listener, or leaving rollback processes active. Implementation template: independent authorization → ownership snapshot → normal profile disabled → cold start/probe → exact stop/restore → non-reusable evidence.

Implementation is ready but execution remains BLOCKED. `i10-agent-lifecycle.cjs cold-rollback` derives the current bound identity without consuming normal LIVE authority, requires `HENGZHUN_AUTHORIZE_FLOWISE_COLD_ROLLBACK=<exact identity>`, rejects active normal or pre-existing cold state, verifies Flowise absence, snapshots the normal v4 evidence tree, runs the legacy four-service cold lifecycle, and accepts success only after exact `harness/mcp/worker/flowise` stop, absent cold state, absent Flowise and an unchanged normal evidence hash. It writes one immutable record under the separate `flowise-cold-rollback-v1` evidence root with `evidenceReusableByNormalProfile=false`. Offline fault injection is complete; the real cold path was not started.
