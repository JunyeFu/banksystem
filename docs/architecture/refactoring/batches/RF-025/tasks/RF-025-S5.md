# RF-025-S5 Human Decision Task

Re-read all current evidence and present one immutable decision proposal to the project owner. Business rule: machine gates can establish eligibility but cannot authorize release. Common failures: generating GO from test counts, accepting a stale public readback, editing a prior decision, or conflating rollback success with product acceptance. Implementation template: current evidence projection → exact identity and 18/18 check → eligibility → explicit human `GO` or `NO_GO` → immutable decision record.

Implementation is ready but the human gate remains BLOCKED. The evaluator accepts cold-rollback evidence only when it is immutable, same-identity, non-reusable, proves all cold services stopped and leaves normal evidence unchanged; it then performs a second final bound CLI readback before emitting `ELIGIBLE_FOR_HUMAN_DECISION`. Recording requires the explicit exact value `HENGZHUN_PROJECT_OWNER_RELEASE_DECISION=<GO|NO_GO>:<identity>`, re-evaluates every gate, freezes the eligibility hash and three evidence pointers, and writes one immutable project-owner record. Missing authority or `NOT_READY` creates no file; a conflicting later decision cannot edit the record. No real GO or NO_GO was supplied or recorded.
