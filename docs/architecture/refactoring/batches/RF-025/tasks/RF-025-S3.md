# RF-025-S3 Release Gate Task

Aggregate supply-chain, DPAPI restore and current readback evidence only after v4 reaches 18/18. Business rule: every release gate must refer to the same bound v4 identity and current source/runtime. Common failures: cached audit reuse, a restore drill on another identity, dirty-tree package claims, or treating installability as business acceptance. Implementation template: ledger status → identity/readback → SBOM and lock check → isolated DPAPI restart/restore → fail-closed eligibility projection.

Implementation is ready offline. `i10-agent-release-decision.cjs` reads the current bound source identity and v4 ledger itself, stops before public readback/audit/DPAPI while 18/18 is absent, then requires same-identity bound CLI readback, deterministic current SBOM, three live high/critical dependency audits and a temporary CurrentUser DPAPI restart/restore. Caller-supplied gate results are not a command input. Even when every S3 gate passes, the projection remains `NOT_READY` with `nextGate=COLD_ROLLBACK`; it cannot create `GO`, `NO_GO` or `ELIGIBLE_FOR_HUMAN_DECISION` before S4/S5. Current execution remains blocked because the source is unbound and the v4 ledger is not 18/18.
