# RF067-S1：会话持久化与MCP

## 业务目标

Harness SQLite保存会话和安全消息，浏览器刷新、Controller检查点派生和进程重启均不改变会话身份或重放执行。工作量1–3天，状态只查BANKSYSTEM-RF067-CONVERSATION-STATE-001。

## 输入与输出

输入：RF066-S1合同与真实生产服务行为刻画。输出：一份增量迁移、业务Repository、带认证的Harness/MCP元数据操作及隔离重启证据；CLI接线归RF066，不在本包实现第二个执行器。

## 实现

2026-10-24回接RF068-S5的V3修复：MCP Journey脱敏投影保留已有error.category/errorCode/recoverable，避免丢失Worker模型拒绝原因。只改mcp/src/journey-evidence-projection.cjs、server.cjs及已有MCP测试，无新工具、迁移或Harness写入行为。真实MCP隔离回归、私密字段反例通过后回接S5冻结。具体顺序、白名单及完成门见RF068 tasks/S5.md。

2026-10-23按RF068-S5修复方案RP03补一个本机验收只读能力，精确路径为`harness/src/workbench-repository.ts`与`scripts/verification/workbench-persistence.test.cjs`（产品根内）：按namespace+Journey读取全部run/task引用、attempt_count、run.claim数及关联turn，使用同一只读事务；不受Quality展示200条上限影响。本机可信托管检查脚本消费该Repository，不新增HTTP/MCP工具、迁移或状态写入口。验收覆盖201条背景运行、新增目标运行、无关Journey不干扰及跨namespace拒绝；原会话/停止状态机保持。本补充不是重做已完成持久化包，其回执归本批索引并回接RF068-S5。

| 小任务 | 具体落点／规则 | 验收产物 |

| BE-P01 | 一份新增SQLite迁移（实施时核实下个空闲号，当前候选044）；存conversation、message/turn、事件和模型元数据，明确namespace、稳定ID、版本与检查点/Journey/Run关联 | 向前迁移、原历史仍可读，模型密钥不入库 |

Repository保存的是会话事实和执行引用，不复制银行余额或独立决定PASSED/GO；运行结果继续回读既有Harness执行账本。NEEDS_INPUT续接建立新消息/turn与原任务关联，不靠完整聊天上下文重建。模型配置只存安全元数据和本机密钥引用，不存API Key、原始模型推理、Cookie或凭据正文。

允许路径：harness/src/**、harness/migrations/**、mcp/src/**、contracts/mcp/**、scripts/verification/**（以上均在platform/hengzhun-regression-system下），根scripts/test/verify-agent-workbench.ps1及本批文档。禁止改银行、Keycloak、Flowise、CLI/Controller生产代码或前端。最多打开Harness与MCP两模块。

## 项目易错点

检查点分叉不是新浏览器对话；现有sessionShow没有transcript。MCP textResult默认8KiB，Harness有分级绝对上限；为本投影明确预算，不能全局调大或直接返回整个历史。旧模型配置版本不能被更新后覆盖运行任务绑定。仅导入一份迁移，不改旧迁移校验和。
