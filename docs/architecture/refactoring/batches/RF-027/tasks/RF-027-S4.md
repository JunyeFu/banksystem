# RF-027-S4：独立干净克隆复现证明

## 业务目标

从当前候选源码生成一个不包含忽略文件、凭据、预构建门户 `dist` 或 Agent 运行时的临时 Git 提交，并通过真实 `git clone` 在独立目录完成完整产品准备、启动、状态回读、停止和清理。当前权威工作区与已恢复状态不得被测试修改。

## 输入与输出

- 输入：当前非忽略源码、Docker Desktop、Java 21、网络和原项目已配置的三个 BYOK 值。
- 输出：候选源码清单摘要、临时提交、干净克隆证明、`PREPARED`、`READY`、`STOPPED`、隔离资源清理结果和原状态前后摘要。
- 证据等级：本机干净源码目录的 `INTEGRATION`，不包含 GitHub 下载、新机器、银行黄金业务、模型推理测试、Full18 或发布裁决。

## 实现

1. 只复制 `git ls-files --cached --others --exclude-standard` 返回的当前候选文件到临时源仓库；拒绝路径逃逸，并生成临时提交后用 `git clone --no-hardlinks` 建立独立目录。
2. 克隆初始状态必须干净，三个门户不得存在 `dist`，Agent 不得存在 `.data`、Node 运行时、`node_modules` 或浏览器缓存。
3. 不复制 `.env`、`runtime.env` 或凭据目录。验证器只解析原项目配置中的三个 BYOK 键，在内存中注入克隆子进程，输出仅包含模型名和 base URL 摘要。
4. 两个 Compose 文件允许设置不同的测试项目名；默认项目名、端口和网络保持不变。克隆使用隔离项目名和新卷，原六卷不挂载、不删除。
5. 执行 `prepare -> up -> status -> down -> reset`。首次确定性失败停止验证，仅继续停止 Agent、删除隔离容器/卷、清除临时凭据和复核原状态。
6. 成功时要求 `up/status=READY`、身份连续、`down=STOPPED`、隔离卷已删除、克隆源码仍干净、原项目服务为零且原 Agent/六卷内容摘要不变。

## 项目易错点

- 从当前仓库直接 `git clone` 只会得到 `HEAD`，不会包含未提交候选实现；临时提交必须由当前非忽略候选树生成，且不得修改 `main` 或用户索引。
- 单一 `COMPOSE_PROJECT_NAME` 会把 Core 与 Channel 合并为同一项目；两个 Compose 项目必须使用不同覆盖值。
- `prepare` 会生成克隆本地秘密和下载 Agent 运行时；这些属于任务临时状态，不能回写原工作区或作为源码提交。
- Docker 镜像缓存和服务健康属于基础设施证据，不证明客户登录、转账或 CLI Agent 真实执行。
