# RF-027-S3：空卷冷启动与复现证明

## 业务目标

证明当前源码快照在无银行与测试平台持久状态时能够重建完整服务拓扑，并在一次停止后从新建持久状态再次启动。当前脏工作区不冒充全新 Git 克隆；全新克隆外部复验保留为 A02 发布前验收项。

## 输入与输出

- 输入：已完成的 S1/S2、RF-029 浏览器运行时、当前 BYOK 三变量、Docker Desktop 与 Java 21。
- 输出：原状态清单、备份归档及 SHA-256、空状态证明、两次 `READY` 状态、两次受控 `down`、恢复后清单及 SHA-256。
- 证据等级：最高为本机 `INTEGRATION`，不包含银行黄金业务、模型 LIVE、Full18 或发布裁决。

## 实现

1. 为生命周期合同增加精确 reset 所有权断言；整个 Agent `.data` 不得作为单一删除目标。
2. `reset` 只删除当前产品可重建的运行状态和两个 Compose 文件当前声明的命名卷，不删除历史证据、备份、凭据或不再声明的旧卷。
3. Linux 容器直接执行的 PostgreSQL 初始化脚本必须使用 LF 行尾，合同测试拒绝 CRLF。
4. 新增受控冷启动验证器：确认服务已停，归档并校验当前声明卷与需要替换的 Agent 当前状态；执行 reset；证明目标状态为空；执行 `prepare -> up -> status -> down -> up -> status -> down`；最后自动恢复原状态并校验。
5. 首个确定性失败立即停止进入验证阶段；无可校验备份时禁止执行 reset。失败时仅保存不含环境变量和日志正文的 Compose 状态摘要。

## 项目易错点

- Compose 健康只证明服务拓扑，不证明客户登录、转账或 Fineract 账务结果。
- `mifos-channel_channel_pg_data` 是当前 Compose 不再声明的旧卷，不属于本次 reset 或冷启动证明。
- `.data` 同时包含历史证据、备份、凭据和当前运行状态；禁止递归删除整个目录。
- ReleaseIdentity 由源码、合同、模型绑定和清单决定；仅清空运行数据不应伪造新身份。

## 完成门

验证器必须在可校验备份存在后才删除当前声明卷；同一源码与模型绑定下两次启动均为 `READY`，停止后项目运行容器为零，原状态自动恢复且哈希匹配。S3 关闭后 RF-027 可获得本机空卷冷启动 `INTEGRATION` 证据，但“全新克隆”仍须在干净源码目录或新机器独立复验。
