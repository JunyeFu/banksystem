# RF-052 S1 audit and event delivery closure task

## Business goal

Operators can trust that concurrent business actions append one tamper-evident audit chain, and event projections can distinguish published, retrying and dead-lettered events without applying the same event twice.

## Implementation

Serialize audit append in PostgreSQL, hash all stored record fields, fail on invalid metadata, atomically lease each Outbox event, publish the contractual event identity, preserve `DEAD_LETTERED`, and use the Inbox primary key as the consumer claim.

## Verification

Use the RF-052 evidence index. Completion requires concurrent append and tamper tests, dual-publisher and DLQ tests, retained-state migration and audit verification, the existing bank golden path, and managed-service keepalive.
