# RF-045 Target Design

The CLI reads the approved Journey and uses its frozen target system, entry URL, credential reference, and optional explicit registered adapter to prepare and exactly approve one Harness-owned TargetProfile through MCP. The controlled bank route is selected only by `journey author --adapter fuxing-bank-demo`; target name, URL, or model prose cannot select it. It then invokes one MCP mutation at each Harness-declared next action, waits on Harness-owned asynchronous state, activates the exact certified candidate, confirms one on-demand execution, submits the bound Run, and reads the Task. The Worker maps Chinese existence assertions to their concrete trailing business noun, including `及对应的可用余额` to `可用余额`, before Midscene locator evidence is evaluated. An explicit read-only navigation disjunction is compiled as alternative visible labels and accepts exactly one matching destination; this does not relax mutation-control matching. Generated navigation waits compare against the URL captured immediately before a paired click, or the current page when no click is paired, so redirects from the configured launch URL cannot satisfy the next wait prematurely. Authoring, stability, and formal execution share the same frozen browser-origin policy; the bank identity-provider origin is available only through the registered adapter binding. Candidate stability failure is projected to the Journey with its exact error and batch ID instead of being hidden behind a CLI polling timeout. The CLI never calls Harness, Worker, browser, SQLite, or Fineract directly.
