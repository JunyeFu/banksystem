# RF-055 S2 fixed demo identity task

## Business goal

A user can start the demo repeatedly and log into both portals with stable synthetic identities whose banking mapping survives restart.

## Entry and boundaries

Entry is `demo.ps1 prepare/up`. `prepare` persists credentials locally and `up` provisions runtime users and mapping after Keycloak/Fineract are ready. Passwords are local secrets, not fixture content or logs. Only S2 allowed paths may change.

## Implementation

Provision one customer and one operator idempotently in Keycloak, assign required roles, bind the customer subject to `customer.alice`, and make the retained startup use these identities instead of generating fresh users for the demo path.

## Done

- Two provisioning calls resolve the same Keycloak IDs and customer mapping.
- `scripts/demo/verify-fixed-demo-identities.ps1` exits 0 before and after restart.
- Customer and operations protected API reads both succeed; no secret is printed.
- Upward synchronization is complete before S3.

## Result

`demo.ps1 prepare` exited 0 and generated four `DEMO_*` keys only in ignored `.env`. Two provisioning calls returned the same customer and operator IDs and Fineract client ID 1. Playwright logged into the Customer Portal with the fixed customer, read one real account, and completed the Operations Console OIDC code flow with the fixed operator. After a controlled Bank Channel container recreate, the same browser verification passed again. Services remained running.
