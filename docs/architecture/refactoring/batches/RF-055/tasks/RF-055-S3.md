# RF-055 S3 Test Support runtime isolation task

## Business goal

Demo automation can manage synthetic fixtures without exposing test mutation routes from the production Bank Channel listener or starting a fake clearing system by default.

## Entry and boundaries

Entry is Compose plus Gateway routing. Only S3 allowed paths may change. Public customer and operations routes, retained data and service keepalive must remain unchanged.

## Implementation

Register the controller only in a dedicated Test Support profile and service, target it from the demo Gateway, and move Mock Clearing behind an explicit Compose profile. Do not add fallback routing.

## Done

- `docker compose ... config --services` omits Mock Clearing by default.
- The main Bank Channel listener returns 404 for the Test Support seed route.
- The dedicated listener accepts an authorized seed request.
- All affected product services and retained services are running after verification; the retired Mock Clearing container is stopped but preserved.
- All RF-055 control and evidence documents are synchronized.

## Result

The default Compose set includes `test-support-service` and excludes `mock-clearing-service`. The Gateway routes Test Support only to the dedicated service. A valid TEST_SUPPORT token returned 404 on the main Bank Channel listener and completed an authorized fixture seed through the dedicated route. The two-cycle fixture verifier and both real browser login flows passed after the cutover. All core bank and channel product containers remain running; only the retired Mock Clearing container was stopped, without deleting its container or volumes. `demo.ps1 up` reached Agent startup but stopped at `AGENT_LIVE_NOT_AUTHORIZED` because the previously approved ReleaseIdentity is stale after RF-055 source edits; no authorization value was changed.
