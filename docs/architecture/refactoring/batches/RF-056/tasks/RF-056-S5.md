# RF-056 S5: Payment, EOD and audit repositories

## Business goal
Transfers, EOD and audit remain transactionally correct while application coordination no longer owns SQL.

## Input and output
Existing 26 direct SQL holders and Channel tables; output is per-module repositories and an application-level EOD coordinator.

## Implementation
Migrate remaining SQL holders, preserve transaction/lock lifetime, move EOD coordination out of payments, keep Fineract posting path unchanged.

### S5-1: Payment persistence
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/payments`, `.../notifications/NotificationRepository.java`, `.../identity/CustomerIdentityRepository.java`, matching tests.
- Move transfer, reversal, receipt, state transition, clearing, inbox and outbox SQL into owning repositories. Keep business decisions and transaction boundaries in existing services; never hold a transaction over a Fineract network call. Reuse notification and identity owners for those tables.
- Done: repeated transfer and reversal, core unknown-result readback, outbox claim and inbox deduplication tests pass; affected payment Controller/Service classes own no JDBC.

### S5-2: EOD application coordination
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/{operations,payments,reconciliation,audit}`, matching EOD tests.
- Move EOD orchestration and step runner to the operations application package. EOD repository owns run/step SQL and returns a connection-held advisory lock handle that is closed only after the full run. Preserve short registration/checkpoint/finish transactions and step order.
- Done: embedded-PostgreSQL single-lock, interruption/resume and no-repeat core-job tests pass without advancing the retained demo Fineract date.

### S5-3: Risk, reconciliation, audit and projections
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/{risk,reconciliation,audit,operations}`, matching tests.
- Move each domain's reads/writes to its own repository. Keep audit advisory transaction lock, predecessor hash and append atomic; keep risk row lock and reconciliation conditional writes. Dashboard and monitoring use read-only projections.
- Done: audit hash verification, risk approval, reconciliation and dashboard tests pass with no Controller/Service JDBC holder.

### S5-4: Test Support and closure
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/{FixtureLifecycleService.java,TestSupportController.java,identity,beneficiaries,notifications,payments,reconciliation,audit}`, matching tests, RF-056 control files.
- Route fixture writes through owning repositories and assertion reads through owning queries/read-only projections, not a cross-domain write repository. Remove the final direct SQL fields from the 20 baseline holders; rerun Java, governance/docs and bank-only runtime gates before marking S5 complete.
- Done: zero Controller/application-Service JDBC/DataSource fields, retained services and volumes untouched, golden transfer and operations readback pass. S6 remains blocked until evidence is recorded.

## Project pitfalls
An EOD lock cannot be released before coordination finishes; posting ambiguity must not be retried blindly.
