# RF-056 S4: Customer and document repositories

## Business goal
Customer and operations documents retain their behavior while SQL ownership moves out of Controllers and stale status updates are rejected.

## Input and output
Existing Channel tables and `operations_document.version`; output is business repositories plus PATCH `{status,version}` and 409 conflicts.

## Implementation
Move only customer/document SQL to owning repositories. Keep service transactions. Update OpenAPI, client and operations UI together; perform version-conditional transition writes.

### S4-1: Customer-owned repositories
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/{customerprofile,beneficiaries,notifications,identity}`, matching `src/test` files.
- Move loan application/approval/document SQL, beneficiary SQL and notification SQL into their module repositories. Preserve loan row locks, conditional writes, transaction scope, core idempotency and missing-identity HTTP semantics. Reuse the existing identity repository for the loan's linked-client query.
- Done: the four named customer controllers/services hold no JDBC/DataSource; loan, beneficiary and notification regressions pass.

### S4-2: Operations document state machine
- Paths: `services/bank-channel-service/src/main/java/local/bank/channel/documents`, matching `src/test` files.
- Repository owns list/read/insert/download and conditional `document_id + status + version` updates. Application service owns validation, transitions, transactions and success-only audit. Missing/invalid input is 400, absent ID is 404, stale or illegal transition is 409.
- Done: embedded PostgreSQL concurrency test yields one winner; upload/download and audit semantics remain intact.

### S4-3: Contract, UI and runtime closure
- Paths: `contracts/openapi/operations-api.yaml`, `packages/bank-api-client/src`, `apps/operations-console/src`, matching tests, this RF-056 control chain.
- Change PATCH to `{status,version}` with documented 409, regenerate client type, send row version and show a conflict with list refresh; no auto-retry. Run Java 21, client, UI, contract, governance and docs gates, then replace only Bank Channel, Test Support and Operations Console images and verify document workflow plus bank golden transfer.
- Done: public routes other than the PATCH body are unchanged; evidence is recorded before S4 is closed or S5 unlocked.

## Project pitfalls
`DRAFT -> PUBLISHED -> ARCHIVED` is the only legal path; two simultaneous updates must not both succeed. No migration is needed.
