# RF-056 S2: Shared customer identity query

## Business goal
Customer account and statement pages resolve the same persisted identity without Controller-to-Controller calls.

## Input and output
`customer_identity` mapping and authenticated subject; output is the linked Fineract customer ID through a query service.

## Implementation
Extract the lookup from CustomerController, inject it into CustomerController and StatementController, keep response types and error semantics unchanged.

## Project pitfalls
Statement currently imports CustomerController and its mapper; do not duplicate the identity SQL.

## Done
- `services/bank-channel-service/mvnw.cmd test` exits 0 for Customer and Statement tests.
- `rg -n 'CustomerController' services/bank-channel-service/src/main/java/local/bank/channel/notifications` returns no matches.
- Record result in `evidence-index.md` before S3.

## Result

The persisted identity lookup now has a single query service and repository; both Customer and Statement controllers consume it. Java 21 Maven tests exited 0, the notifications package has no CustomerController reference, and both real browser logins and customer reload passed after replacing only the Bank Channel/Test Support image. No public response shape changed.
