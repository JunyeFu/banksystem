# RF063-S4：Agent输入及质量事实

## 业务目标
金额来自明确用户输入、发布结果真实投影。

## 输入与输出
当前工作区源码及既有合同；覆盖问题 M13,M14。输出可检验修复及证据。

## 实现

S4-2/3：RF057生产者为报告绑定当前ReleaseIdentity、清单摘要、结束时间、产物摘要和清理回执；经过service token认证登记到Harness，重复runId不得改写摘要。Harness校验登记报告、当前源码身份、清理与Agent账本后产生发布判定，Quality只投影SQLite判定。demo verify调用同一验证器，未运行项明确NO_GO，不再固定返回占位结果。新增Harness迁移041属于本片唯一执行状态源，不引入第二账本。
建立最小失败反例，沿生产调用链修复，删除失效逻辑。路径白名单：platform/hengzhun-regression-system/controller, platform/hengzhun-regression-system/harness, platform/hengzhun-regression-system/scripts/verification, apps/quality-case-portal, contracts/openapi/quality-platform-api.yaml。控制文件和证据索引允许同片回灌。

## 项目易错点
保留用户脏工作区；远程成功不等于本地完成；现有证据只证明对应源码和运行身份。

## 验证
2026-10-08收尾小任务（仅本片白名单）：

1. 对现有ReleaseVerification补合同测试：当前身份、重复/改写报告、缺失/变更工件、未清理、缺场景、A04缺业务输入无执行、A07指定预期失败。
2. 检验银行/性能结论的证据内容，不从PASSED标签或总数生成GO；Quality在后续非预期失败与STALE_SOURCE时不得继续READY。
3. 运行产品build、注册测试及Quality构建后才由S5接入命令入口；迁移041仅由Harness管理。不增加Quality写接口或第二验证器。

本阶段细化（2026-10-08）：A04 必须证明当前身份的转账输入确实缺金额或收款人，且无 Run、作者化准备或执行任务；缺凭据不能代替该场景。Journey 输入由 Harness 保存运行身份，CLI 直接运行在 NEEDS_INPUT 时返回澄清并停止。A07 校验冻结的指定断言、正式报告中的唯一失败步骤、当前身份和失败任务，并验证五类工件；另一断言失败、执行异常或缺报告均不得豁免。实现文件白名单补 `agent-cli/src/production-service.mjs` 与对应测试；先做反例再修复，不进入新身份 LIVE。

产品根目录 npm.cmd run build；bundled Node --test scripts/verification/quality-read-model.test.cjs；bundled Node --test agent-cli/test/journey-author-validate.test.mjs；quality npm.cmd run build。Harness 无独立 package.json，不虚构 Harness npm test。

## 完成门
金额来自明确用户输入、发布结果真实投影，相关命令退出0且复审未发现本项残留；运行/压力未执行时保持未完成。
