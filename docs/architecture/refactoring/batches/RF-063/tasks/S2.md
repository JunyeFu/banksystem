# RF063-S2：资金及日终失败语义

## 业务目标
短事务、未知只回读、真实总账、日期冲突、故障窗口。

## 输入与输出
当前工作区源码及既有合同；覆盖问题 M05,M06,M07,M08,M09,M11,M12。输出可检验修复及证据。

## 实现

贷款还款/关闭增加具体的 loan_core_operation 持久化状态，以 applicationId+key 绑定命令、金额、核心日期和关联号；领取胜者单次提交，重复请求仅回读，完成状态与审计/outbox 在同一短事务提交。新增 Liquibase v16，扩展 contracts/asyncapi 的贷款操作完成事件；原转账 outbox 的非空约束改为按聚合类型约束。此为 M08 已观察资金不变量修复，不新增通用操作框架。

EOD作业在提交前保存核心运行版本（v17），HTTP接受不算成功；只在回读唯一新增application成功记录后完成步骤。中断后回读原版本，不再次提交；缺记录、cron干扰及失败保持中断。保留环境仅核对作业只读API形状，不执行推进日期的EOD。

本轮继续授权采用新的GL演示基线：仅通过Fineract API建立现金会计产品和新合成账户，更新contracts/fixtures逻辑引用，保留旧账户及历史。对账通过核心账户产品会计规则明确区分历史未启用会计的覆盖边界；新基线逐笔关联储蓄流水与总账，核金额、币种及借贷。继续完成贷款操作持久化和日终作业回读，随后在隔离PG及真实服务验证。
建立最小失败反例，沿生产调用链修复，删除失效逻辑。路径白名单：services/bank-channel-service, contracts/openapi, packages/bank-api-client。控制文件和证据索引允许同片回灌。

## 项目易错点
保留用户脏工作区；远程成功不等于本地完成；现有证据只证明对应源码和运行身份。

## 验证
2026-10-08收尾小任务（仅本片白名单）：

1. 核对LoanOperationService/Repository及LoanWorkflowService的领取权、请求绑定、未知结果回读和审计/outbox短事务；覆盖重复、异体键和失败窗口。
2. 核对EodCoordinator/StepRunner/Repository的作业版本、恢复、全局写屏障及贷款在途状态；在隔离PG测试中验证，不调用保留核心的推进日期作业。
3. 复审Fineract总账关联和币种平衡；运行Java21全套回归，汇总Surefire结果到证据索引。旧运行成功仅注明当时源码/镜像范围，不追记当前身份成功。

已观察M12残留：LoanWorkflowService.submitToCore未持有CoreWriteRepository共享会话锁，日终独占锁期间仍可领取key并POST。隔离PG反例`coreSubmissionCannotClaimOrPostDuringEod`在修复前失败（预期409但未抛出）。复用现有屏障覆盖领取、网络调用和落地，异常释放；补阻断零领取/零POST以及网络失败释放/未知仅回读测试。不增加事务跨网络、迁移或新锁。

Java21 mvnw.cmd test; embedded PostgreSQL failure/concurrency tests；失败保留原因，修复后重跑受影响门。

## 完成门
短事务、未知只回读、真实总账、日期冲突、故障窗口，相关命令退出0且复审未发现本项残留；运行/压力未执行时保持未完成。
