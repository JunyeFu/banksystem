# S2：隔离银行与浏览器集成

## 业务目标
空库播种后真实转账及运营回读，余额守恒，浏览器路径和Agent工具合同可验证。

## 输入与输出
S1通过，独立容器项目/空卷与合成凭据；输出黄金链/浏览器证据。

## 实现

### S2-1：独立拓扑与空库黄金链

S1验收后关闭其governance.refactoring/hengzhun.tests实现模块；本片同时只开放frontend.customer-portal与frontend.operations-console两个业务模块。部署生成器与合同测试属于本片验证辅助，不改变银行业务模块。

先运行 `python scripts/test/test_ci_bank_topology.py`，再以测试自有源码快照为输入执行 `python scripts/deploy/prepare-ci-bank.py --source <snapshot> --output <new-test-directory>`。生成单一rf065ci项目、三个空命名卷、独立内部网络；只包含PostgreSQL/Fineract/ActiveMQ/Keycloak/Channel/Test Support/Gateway/客户与运营门户，不启动Mock Clearing或模型。合成凭据由生成器创建，不读取原.env/secrets。公开核心初始化脚本只负责建库/用户，不伪造业务数据。

构建：`docker compose -f <output>/compose.json build`；先启动核心：`docker compose -f <output>/compose.json up -d --wait postgresql activemq fineract-server`，再用 `pwsh -NoProfile -File <snapshot>/scripts/deploy/ensure-fineract-credentials.ps1 -EnvironmentPath <output>/synthetic.env -BaseUrl http://127.0.0.1:21100/fineract-provider` 轮换新库初始密码；最后 `docker compose -f <output>/compose.json up -d --wait` 启动Channel/门户。首次失败即停止后续验证，保留该测试项目的报告；原项目保持运行。仅在核对项目标签后允许停止测试项目，不删卷。

黄金链：`pwsh -NoProfile -File <snapshot>/scripts/demo/run-golden-path.ps1 -EnvironmentPath <output>/synthetic.env -GatewayBaseUrl http://127.0.0.1:21443 -KeycloakBaseUrl http://127.0.0.1:21900 -FineractBaseUrl http://127.0.0.1:21100/fineract-provider`。初始Fineract管理员仅在新空库使用发行版初始凭据，后续按已有ensure-fineract-credentials入口建立隔离服务账号，不引用原账号。

### S2-2：真实门户登录与业务复核

已观察两门户硬编码19000 issuer会连到原Keycloak；改构建参数VITE_OIDC_ISSUER，默认保持原地址。只在隔离镜像指定21900，派生测试realm的redirectUris/webOrigins为21882/21883；不修改原realm。精确扩充白名单为两门户src/auth/oidc.ts与oidc.test.ts、infra/frontend/Dockerfile。补指定issuer的授权/token请求单元；浏览器必须登录真实Keycloak，不注入token或使用auth bypass，随后客户/运营回读同一交易与关联号。截图/trace仅输出测试专属目录；无模型调用，不作RF057正式LIVE。

银行API黄金链通过后执行 `node scripts/test/ci-bank-browser.cjs <output> <snapshot>`（冻结Node20）；脚本使用已准备Playwright/Chromium，Browser plugin not available。真实客户/运营两独立BrowserContext登录，页面提交1.00 CNY、复核SETTLED、核心参考号/关联号、运营同一交易，并经Fineract API核对双方余额分增减与守恒、Channel投影平衡。凭据只在内存和测试自有synthetic.env，结果JSON不包含token/密码；只在登录完成后截图，不采集含认证网络的原始trace，不冒充正式发布证据。首次失败保存脱敏阶段/错误码并返回非零，不重试资金动作；关闭自己的浏览器Context并仅清理自己的Keycloak身份，测试业务记录保留在自有卷。

### S2-3：CI接线与验收

#### S2-3-L：本机等价Linux验证

只读WSL探测已确认Ubuntu可访问Windows隔离银行loopback，docker.exe互操作可连接同一引擎；此前native docker/pwsh缺失不是业务失败。不改Docker WSL设置，官方Node20.20.2/PowerShell7.6.5便携工具及锁文件依赖只装测试专属目录。复用公开源码过滤规则生成新的source-snapshot，不复制原凭据/运行状态或Windows node_modules。为保留现有04服务，生成器增加本次所需显式port-offset=1000：22100/22443/22882/22883/22900，CI默认仍原端口。ownership携实际端口，realm/issuer及浏览器仅从该新项目配置取得地址；增加偏移拓扑合同，先登记端口并核对空闲。

在Windows仅运行生成器与docker.exe，构建新项目/三个空卷；Ubuntu Linux PowerShell执行原密码轮换与黄金链、Linux Node20/Chromium1217执行浏览器。该组合证明Linux测试入口及真实空库银行行为，不声称GitHub远端执行或产品Linux安装；Docker引擎仍原Desktop。每步成功才下一步，确定性失败停止，所有自有失败证据保留；不关04/原服务。必要路径仍只scripts/deploy、scripts/test及本片控制文档。

WSL HTTPS独立探测已出现SSL connection timeout，而Docker构建内npm下载正常；不改系统代理或网卡。便携官方工件经Windows下载核对官方摘要，Linux锁文件依赖/Chromium下载改由一个自有无端口helper容器执行，固定官方Node20.20.2 Debian amd64摘要3d0f05455dea2c82e2f76e7e2543964c30f6b7d673fc1a83286736d44fe4c41c（官方manifest现场回读）。helper仅挂载新测试runtime目录，不读合成银行凭据/原状态，npm按锁文件真实安装；产物仍供UbuntuLinux入口使用。取消已核对的WSL npm进程后保存其部分目录与失败日志，不能重放资金或续写旧安装成功。helper容器记录项目标签，不连接原业务网络、不挂原卷。

新增bank-browser-integration作业，使用ubuntu-24.04原生Docker；既有五组Windows检查保持。checkout明确放banksystem-rf065/source-snapshot，生成器只在同级bank目录创建新项目及空卷。依次构建、空库核心启动、生成凭据轮换、十服务健康、100.00黄金链、1.00真实页面转账与运营回读；失败不进入后续步骤、不重试。Playwright按runtime锁文件安装，Linux Chromium显式路径chromium-1217/chrome-linux64/chrome，驱动校验实际版本等于冻结147.0.7727.15；Windows既有调用保持冻结路径。仅上传脱敏黄金结果、浏览器成功/失败JSON及两张截图，禁止上传synthetic.env、compose.json、realm、认证网络trace或容器原始日志。临时runner生命周期结束由GitHub销毁，工作流不执行down/reset/删卷。

本地workflow合同、拓扑合同、解析测试验证接线；Linux runner实际执行仍需远端CI证据，不用Windows本地成功代替。未获提交/推送授权不触发远端。S2在远端运行或等价Linux实测前仍IMPLEMENTING；已通过本地业务门可以保留，不重复资金操作。

#### S2-1-F1：空库贷款产品播种修复

第二轮空库十服务健康，黄金链在SEED_FIXTURES失败，未提交转账。Fineract贷款产品400明确缺daysInYearType、daysInMonthType、isInterestRecalculationEnabled。只读新库loanproducts/template确认Actual枚举均为1、重算关闭false。固定合成演示贷款使用Actual/Actual且不启用利息重算；在FineractLoanPort.createLoanProduct写出这三项，不删除贷款播种、不改账务库或公开API。

前端实现模块暂收口，本次仅开放bank.test-support。精确追加两路径：services/bank-channel-service/src/main/java/local/bank/channel/FineractLoanPort.java、services/bank-channel-service/src/test/java/local/bank/channel/FineractCapabilityHttpTest.java。新增本地HTTP请求合同，检查三个必填值与路径/结果；Java21全套通过后从新的空库项目起点重跑，旧02失败不续写成功。命令为 `mvnw.cmd --batch-mode --settings ../../scripts/test/ci-maven-settings.xml test`（Java21）；首次确定失败仍停止后续。

#### S2-1-F2：场景账户来源一致性

第三轮贷款播种通过，场景LOAD_ACCOUNTS失败。只读源码确认FixtureLifecycleService按baseline-fixtures创建banksystem-gl-v1账户，而TestSupportController仍硬编码旧banksystem-demo账户。改场景读取现有FixtureCatalog中account.alice.primarySavings/account.bob.primarySavings.externalId，不复制或恢复旧账户。增加使用实际目录的调用合同，验证两个核心查询均来自目录；查不到账户仍明确失败，不资金重试。精确追加TestSupportController.java与TestSupportScenarioContractTest.java，仍仅bank.test-support模块。Java21全套通过后第四个新空库从起点验证，第三轮失败保留。

#### S2-1-F3：流水回读失败不得补款

复审同一场景方法发现catch(Exception)吞流水读取错误，转而使用Channel审计决定是否向Fineract deposit；这违反已建立的核心真相/未知结果不盲写边界。删除该回退，回读错误返回已有FAILED/CHECK_TRANSACTIONS，无deposit。用同一TestSupportScenarioContractTest的ACTIVE账户+流水异常反例验证失败阶段及never deposit。仍只改已登记两文件，不新增接口、数据库或兼容路径；Java21全套及治理通过后才第四轮新空库验收。

#### S2-2-F1：Windows环境行结束符

第四轮API黄金链已通过，浏览器驱动SETUP认证401停止，未发生页面资金动作。测试生成的synthetic.env为CRLF（17 CR/17 LF），Node仅split LF把CR带入用户名/密码；PowerShell黄金链按行读取所以通过。仅规范行结束符，不trim凭据内容；scripts/test/ci-bank-browser.test.cjs用合成LF/CRLF、等号和空格证明解析一致。保留首次失败文件后以同一银行项目启动新的浏览器验证进程，禁止重放已完成100.00转账；该修复不改银行源码或数据库。

空库和浏览器实测通过后才接入公开CI；同一入口返回非零失败并上传脱敏报告。远端未运行不标绿；S1仍仅本地源码门，S2通过后再进入S3。端口21100/21443/21882/21883/21900先登记并核对空闲再启动。
复用现有银行测试脚本，独立拓扑/卷，不使用原演示库；无需BYOK的确定性适配器仅限CI。
路径白名单：scripts/test, scripts/deploy, .github/workflows。每片控制1–3天，不改变产品API或业务状态。

证据伴随同步包括既有docs/current-state/lifecycle-workbench.md和外部站点：纠正仍将已确认需求描述为“待后续PRD输入”的滞后投影，引用现有规范化源稿；不另建产品状态或实施顺序。
