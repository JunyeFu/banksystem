# P2 v1.1 实施基线与门禁

本文件记录 2026-07-12 只读审计后的真实实施基线，优先级高于 v1.0 计划中的任何冲突描述。

## 当前事实

- 运行库已执行 P2-2 的前三个 changeset；`idempotency_record` 已有 `id`、`scope_key`、`status`、`resource_id`、`expires_at`。
- `transfer_outbox` 仍存在，`outbox_event` 尚不存在；P2-3 未迁移。
- 当前源码已混入 P2 SQL，但转账幂等仍访问旧列，outbox SQL 同时出现旧表和新表语义。
- master changelog 当前遗漏 P1 的 `v2-p1-transfer-status.yaml` include，必须先恢复。
- 当前渠道服务停用；禁止用半成品源码直接启动。

## 不可违反的实施规则

1. 不修改已 RUN 的 `v3-p2-2-idempotency-*` changeset；所有修复新增 changeset。
2. 在 P2-2 完成应用层兼容前，不删除 `idempotency_key`、`response_body`、`status_code` 等旧列。
3. P2-3 迁移前，所有会运行的应用 SQL 必须继续读写 `transfer_outbox`；切换应在同一停机窗口完成。
4. 所有监控和脚本使用 P1 的 12 态，不得重新引入旧状态名称。
5. 数据库切换前执行可恢复备份；迁移后以新的写入、发布、重试和幂等测试证明可用。

## 需补齐的验证

- P2-2：相同请求重放、不同请求冲突、过期键、迁移前旧记录、迁移后新记录、transfer 外键完整性。
- P2-3：待发布、成功发布、失败重试、DLQ、重启恢复及 AsyncAPI 契约。
- P2-4：matched 与 fallback 两条断言路径，均返回可机器判定的 `correlationIdFilter` 与 `matchedCount`。
- P2-5：真实 PostgreSQL 并发 EOD，验证只推进一次业务日期。
- P2-6：后端 503、`X-Alert: EOD_FAILED`、前端告警对象模型和页面卡片。
