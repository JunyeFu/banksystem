# BANK-0605 execution report

Status: REVIEW

Cross-ownership security correction for Stage 1 acceptance. Customer self-service
routes were incorrectly guarded by `ROLE_CUSTOMER_SERVICE`, preventing a valid
`CUSTOMER` token from reading its own profile. The security policy now requires
`ROLE_CUSTOMER` for all customer API routes, while beneficiary and transfer
creation retain the stricter `ROLE_CUSTOMER_MFA_VERIFIED` requirement.

The previously unguarded `core-submit` route is now explicitly denied together
with the other direct customer-to-core command routes. Validation is the local
customer transfer E2E regression plus the existing unauthorized-access checks.

During that regression, the audit-event insert was found to contain one extra
SQL placeholder. The statement now matches its 15 persisted columns and 15
bound values, allowing audited money operations to complete atomically.

The transfer processor now uses Fineract's configured business date rather than
the host clock, preventing core rejection when the two dates differ. Failed
transfer reason codes are bounded to the database column limit, and the E2E
cleanup deletes dependent state-history and ledger rows before the transfer.
The customer-security E2E cleanup now follows that same dependency order.
The money unit test now verifies the actual binary-floating-point failure mode
while asserting the exact decimal result used by the service.

The Gateway health check now targets IPv4 loopback explicitly. The service
already returned 200 on that endpoint, but the localhost probe reported the
container as unhealthy in Docker Compose.
