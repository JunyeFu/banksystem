# BANK-0301 execution report

Status: DONE

Implemented channel-owned beneficiary and idempotency modules. Beneficiary
account numbers are SHA-256 tokenized and only the last four digits are returned.
Transfer creation requires a 16–128 character `Idempotency-Key`; a repeated key
with the same request returns the original response, while a different body
returns 409. The request and transfer row are inserted in one channel database
transaction and remain `RECEIVED` until the later core adapter task.

Runtime evidence (2026-07-10): an isolated customer token created a beneficiary
through the gateway and retrieved it through the subject-scoped list endpoint;
the response returned a masked account (`****7890`) and exactly one list item.
The temporary Keycloak user/client and channel rows were removed after the test.

`scripts/test/customer-security-e2e.ps1` verifies a replay with the same
idempotency key returns the same transfer ID, while a changed amount returns
HTTP 409 and leaves no test order behind.
