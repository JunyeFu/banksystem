# 个人全栈固定开发工作流

```text
事实基线
→ 垂直业务切片
→ 业务状态机/权限/审计
→ OpenAPI 与 JSON Schema
→ Mock 与生成客户端
→ 后端迁移、服务和接口
→ 前端页面与真实接口
→ 单元、契约、集成、E2E、视觉、安全测试
→ Docker 本机验收与证据
```

## 固定顺序

1. 核验当前代码、契约、测试、容器和未提交改动。
2. 用一个可验收的业务闭环定义切片，不按纯前端或纯后端横向铺开。
3. 冻结角色、状态、权限、金额、幂等、审计和错误语义。
4. 先提交契约与样例，再生成 Mock、类型和客户端。
5. 后端实现数据库迁移、领域规则、接口与契约测试。
6. 前端基于同一契约完成所有页面状态并接入真实接口。
7. 从快速门禁到完整门禁逐层验证。
8. 对需要身份与业务数据绑定的演示环境，分别验证身份登录、身份到核心客户映射、核心业务数据和授权范围；不得用“登录成功”替代“客户数据已就绪”。
9. 只在 Docker 本机可重复启动、重置、验收并形成证据后完成切片；有状态身份服务必须挂载持久卷，并执行一次重建后数据仍存在的验证。

当前项目级顺序只读取唯一实施顺序文件。I8 确定性脚本作者化引擎已完成；I9 当前切片聚焦正式 Flowise Agentflow、MCP、双知识库/双 SQLite、真实正反向对话、跨电脑便携验收和 P9 最终可压缩提交文件夹；银行前端只按首个登录案例收敛，衡准观测 UI 继续暂缓。
