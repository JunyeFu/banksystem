  插件

  1. 插件概述
  由 HiAgent 官方或者其他用户提供的插件工具，也可以自己搭建自定义插件，这些插件涉及
  各类功能，如网页搜索、工具效率等，使用插件，可以帮助你拓展智能体的能力。你可以在编
  排或者工作流搭建时，选择使用。

1. 支持官方插件使用，也可自定义创建插件、导入插件

1. 支持插件的收藏和授权

1. 支持在插件内导入工具或添加工具

1. 支持对工具的启用/禁用，支持工具的 Debug

1. 支持插件的管理，包括删除、编辑、导入、导出、发布插件

  2. 插件中心
  插件中心包含以下两个入口：

1. 应用 > 插件 > 插件中心：展示 HiAgent 官方或其他用户发布上架的插件，以及火山引擎云市
  场的插件列表。

1. 探索 > 插件中心：展示 HiAgent 官方或其他用户发布上架的插件。


  MCP 插件的稳定性依赖于服务提供方，预置的 MCP 插件平台不保证其可用性，可
  在管理后台按需上下架。

  插件中心入口 1
1. 登录 HiAgent。

1. 进入目标工作空间，在左侧导航栏选择应用 > 插件菜单。

   1. 插件：展示当前 HiAgent 插件中心的列表页，及插件总数
  1.支持在插件中心按插件分类、权限类别、关键词模糊搜索（在插件页面可搜索工具名
    称），或通过收藏查看插件。

  1.展示当前插件的插件描述、分类标签、该插件被多少智能体使用、发布时间等基本信
    息。

  1.部分插件显示锁图标，使用需要先授权，在插件卡片上单击设置授权，填写授权申请
    后才能使用。




1. 探索 Marketplace：展示获取到的火山引擎云市场插件列表

  插件中心入口 2
1. 登录 HiAgent。

1. 进入目标工作空间，在左侧导航栏选择探索 > 插件中心菜单。

1. 在插件中心页面，选择需使用的插件。
   1. 默认展示全部插件、可选择我的收藏、我的提交查阅。

   1. 支持按分类筛选。

   1. 支持按需要授权、无需授权筛选。

         需要授权的插件，请参考以下操作步骤进行授权：

      1.在左侧导航栏选择应用 > 插件，在插件中心页签搜索插件名称。

      1.在插件卡片上单击设置授权。

  1. API Key：一种简化的认证方式，其中 API 调用需要某种秘钥
    或令牌来验证其合法性。这种秘钥可能会通过查询参数或请求
    头传递。它是为了确保只有拥有此秘钥的用户或系统能够访问

    1.添加位置：必填，决定了秘钥应该放在哪里传给服务器，

         1. Query：代表秘钥作为 URL 的一部分

         告诉 API 服务，将在哪个参数中提供授权信息。如将

              1.Value：未打开开启开关时必填，一个专属的 API 密钥，代
                表身份或给定的服务权限。API 服务会验证此 Token，以
                确保有权进行相应的操作。如将 abc.com/getInfo?
                token=xxx 中的 xxx 填在此处。

              1.开启：打开开启开关时，插件的使用者需要填写认证信

            1. OAuth2：OAuth2 是一个开放标准，常用于用户代理认证。允
              许第三方智能体在不共享用户密码的情况下访问用户账户的特
              定资源。

              1.grant_type：选择获取访问令牌的授权方式，当前支持
                Authentication Code 和 Client Credentials

              1.client_id：智能体在 OAuth 提供者注册时获取的唯一标
                识，必填

              1.client_secret：与 ClientID 配对的秘密，用于认证智能体并
                获取令牌，必填

              1.redirect_url：智能体的回调 URL，授权码将发送到此
                URL，当 grant_type 为 Authentication Code 时必填

              1.auth_url：用户被重定向以授权智能体的 OAuth 提供者的
                URL。需要进行 URL 验证，当 grant_type 为
                Authentication Code 时必填

              1.access_token_url：用户被重定向以授权智能体的 OAuth
                提供者的 URL，必填

              1.Scope：你的智能体希望访问的资源的范围或级别，非必填

              1.refresh_token_url：用户被重定向以自动刷新智能体授权过
                期的 OAuth 提供者的 URL，不填写表示默认使用
                access_token_url 配置的 URL，非必填

              1.auth_content_type：用于向 OAuth 提供者发送数据的内容
                类型，必填，可选项包含：application/json（默认）、
                application/form-data
