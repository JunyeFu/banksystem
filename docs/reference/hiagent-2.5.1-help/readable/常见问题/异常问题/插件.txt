  MCP 插件调试报网络错误
  问题描述

  MCP 插件调试报网络错误。

  问题分析

  mcp 插件需要实现 HTTP_PROXY, HTTPS_PROXY 代理环境变量, 且默认只能通过代理的方
  式访问网络; 可以通过部署参数, 按需添加 IP 白名单

  部分 npx 插件由于 nodejs 的 fetch 组件不支持代理，而 HiAgent POC 环境内的插件调用出于
  字节安全要求必须走代理访问。因此如果 npx 插件使用该模块访问外网接口，就会出现网络不
  通的情况

  2.1.0 后通过支持 4 层代理解决




  解决方案

1. 如果 MCP Server 支持其他运行方式，建议避免使用 npx，优先使用 SSE 或其他 STDIO 的命
  令（uvx/docker）。

1. 联系平台管理员对要访问的外网地址开白

1. 私部环境根据自身安全要求可以设置不走代理

  工具没有调用
  问题描述

  工具没有调用。

  问题分析

1. 提示词是否合理：有没有尝试优化下提示词，提示词有没有告诉模型要怎么调用工具

1. 工具的名称/描述是否正确，有意义：不要随意写个 test 名称，test 描述。

1. 问题是否正确：有没有错别字，表达不清晰，逻辑模糊的情况。问题和工具，提示词是否有相
  关性。如果大模型是一个小学生，他能不能知道要调用工具来回答你的问题？
  解决方案

  根据问题分析原因进行优化。

  工具调用报错
  常见的工具调用报错有：

1. 模型生成参数错误。这种情况可以尝试通过以下方式优化：

  1. 请检查工具描述，工具字段的描述是否正确无歧义。

  1. 尽量简化入参设计。过于复杂的参数模型就是很难正确生成。

  1. 可以在提示词或者工具描述里，提供一些入参调用的示例。比如：

      Plain Text
      下面是一些工具的调用示例：
      1. 调用天气工具查询深圳的天气，参数为： {"city": "深圳市"}

      以上是所有的工具调用示例
1. 工具执行报错：常见的是网络错误，请检查 runtime-server 和目标网络地址的连通性。

自定义插件编辑更新后，工作流中调用该插件发现新编辑内容未生效
问题描述

自定义插件编辑更新后，工作流中调用该插件发现新编辑内容未生效。

问题分析

检查插件调用结果并查看自定义插件的设置，发现新编辑的内容确实未生效。查看自定义插件
页面时，注意到左上角提示：“插件已被修改，再次发布之前，智能体将继续使用之前发布版
本的插件”根据提示，重新发布插件后进行调用，插件效果已更新。




解决方案

自定义插件编辑更新后，重新发布该插件。

调用自定义插件报错：“ToolOutputExceedLimitException: tool
output exceeded 2097152”
问题描述

调用自定义插件报错：“ToolOutputExceedLimitException: tool output exceeded 2097152”。

问题分析

根据错误提示，插件输出的数据量超过了 2097152 字节（2MB）的限制。通常，插件的输出
结果需要提供给大模型作为输入，但当前的大模型不支持如此大的输入。因此，当前产品设置
插件的输出限制为 2097152 字节（2MB）。

解决方案

建议调整插件输出内容的大小，或者在大文件场景中考虑使用知识库功能。
