MCP插件调试报网络错误

问题描述

MCP插件调试报网络错误。

问题分析

mcp 插件需要实现 HTTP_PROXY, HTTPS_PROXY 代理环境变量, 且默认只能通过代理的方式访问网络; 可以通过部署参数, 按需添加IP白名单

部分npx插件由于nodejs的fetch组件不支持代理，而HiAgent POC环境内的插件调用出于字节安全要求必须走代理访问。因此如果npx插件使用该模块访问外网接口，就会出现网络不通的情况

2.1.0后通过支持4层代理解决

解决方案

如果MCP Server支持其他运行方式，建议避免使用npx，优先使用SSE或其他STDIO的命令（uvx/docker）。

联系平台管理员对要访问的外网地址开白

私部环境根据自身安全要求可以设置不走代理

自定义插件编辑更新后，工作流中调用该插件发现新编辑内容未生效

问题描述

自定义插件编辑更新后，工作流中调用该插件发现新编辑内容未生效。

问题分析

检查插件调用结果并查看自定义插件的设置，发现新编辑的内容确实未生效。查看自定义插件页面时，注意到左上角提示：“插件已被修改，再次发布之前，智能体将继续使用之前发布版本的插件”根据提示，重新发布插件后进行调用，插件效果已更新。

解决方案

自定义插件编辑更新后，重新发布该插件。

调用自定义插件报错：“ToolOutputExceedLimitException: tool output exceeded 2097152”

问题描述

调用自定义插件报错：“ToolOutputExceedLimitException: tool output exceeded 2097152”。

问题分析

根据错误提示，插件输出的数据量超过了 2097152 字节（2MB）的限制。通常，插件的输出结果需要提供给大模型作为输入，但当前的大模型不支持如此大的输入。因此，当前产品设置插件的输出限制为 2097152 字节（2MB）。

解决方案

建议调整插件输出内容的大小，或者在大文件场景中考虑使用知识库功能。

## 表格 4

- 行 1: Exit Code | 名称 | 含义
- 行 2: 0 | 正常退出 | 表示容器正常退出。该状态码不一定表示存在异常，例如，当容器内没有进程时，也会出现退出状态码为0的场景。
- 行 3: 1 | 一般程序错误 | 引起该异常状态的原因较多，大多由于程序自身错误导致，需要进一步通过容器日志定位原因。例如在ARM节点上运行X86镜像时，会出现该错误。
- 行 4: 125 | 容器未能运行 | 发生这种情况的常见原因有如下几种： 命令中使用了未定义的flag，例如docker run --abcd。 镜像中用户定义的命令在本机权限不足。 容器引擎与宿主机操作系统或硬件不兼容。
- 行 5: 126 | 命令调用错误 | 镜像中调用的命令无法执行，例如文件权限不足或文件不可执行。
- 行 6: 127 | 找不到文件或目录 | 无法找到镜像中指定的文件或目录。
- 行 7: 128 | 无效的退出参数 | 容器退出但未提供有效的退出代码，可能的原因有多种，需要进一步定位原因。例如containerd节点上运行的应用尝试调用docker命令。
- 行 8: 137 | 立即终止（SIGKILL） | 表示程序被SIGKILL信号终止，常见的原因有如下几种： Pod中容器内存达到了其资源限制（resources.limits）。例如，内存溢出（OOM）会导致cgroup强制停止该容器。 运行容器的节点本身资源不足（OOM），则节点内核会选择停止一些进程来释放内存，可能会导致容器被终止。 容器健康检查失败，kubelet会停止该容器。 其他外部进程强制停止容器，例如恶意脚本。
- 行 9: 139 | 分段错误（SIGSEGV） | 表示容器收到了来自操作系统的SIGSEGV信号，由于容器试图访问无权限的内存位置引起。
- 行 10: 143 | 优雅终止（SIGTERM） | 表示容器在主机指示后正确关闭。一般来说，退出码143不需要进行故障排除。
- 行 11: 255 | 状态码超出范围 | 表示容器退出状态码超出范围。例如，可能是设置异常退出使用exit(-1)导致的，而-1将会自动转换成255。 出现该异常时无法判断原因，需要进一步通过容器日志定位原因。
