# 衡准自动化回归测试系统 I10 Windows x64 正式版

衡准是一套以 Flowise 为唯一对话入口、通过本机 Harness、Midscene 和 Playwright 完成自动化回归测试闭环的 Windows 便携系统。本目录自带 Node.js、Flowise、Chromium、FFmpeg、OCR、Harness、Worker 和 SQLite 迁移，不要求安装 WSL、Docker 或全局 Node.js。

## 文档与运行制品权威

当前事实以实际代码、SQLite 状态和真实运行证据为准；完整端到端链路、目标状态机和未落地能力以工作区的《衡准-I10-完整链路审计文档》为设计权威。正式 Agentflow JSON、运行配置、机器合同、验收矩阵和历史说明均为派生或辅助材料，只有与代码和审计文档一致时才有效。

若实现与目标设计不一致，必须明确标记为“实现与设计不一致”，不得把目标设计写成已完成能力。当前正式 Agentflow 为 v6；v5 和 v4 均仅作为回退制品，不作为当前行为事实。

PREPARE 只校验 SQLite 迁移输入；实际迁移由 Harness 启动时执行。图片输入采用纯 OCR 链路。v6 的构建、发布和验证边界见 [I10 Agentflow v6 本机收口](flowise/i10/i10-agentflow-v6-closure.md)。

支持环境：Windows 10/11 x64、本地可写磁盘。目录可以位于含空格或中文的路径中。

## 一、系统边界

- Flowise：唯一自然语言入口和主控工作流平台。
- 主控模型：理解案例、追问信息、结构化输入、解释结果和限域修订候选脚本。
- Midscene与视觉模型：只做视觉作者化、页面理解和元素定位建议；不点击、不输入、不滚动、不签发脚本。
- Playwright：唯一的浏览器执行器，负责确定性操作、断言、取证、脚本验证和正式回归执行。
- Harness：鉴权、幂等、状态机、证据、调度、审计和SQLite数据管理。
- Worker：执行Midscene作者化和Playwright任务。
- MCP：Flowise访问本机Harness的唯一工具边界。

正式脚本不由Midscene直接签发。完整链路固定为：

```text
用户输入
→ 主控模型结构化
→ 人工确认案例
→ Midscene视觉作者化
→ ActionTrace
→ 确定性Builder生成Playwright源码
→ 纯Playwright验证
→ 2个视口×每个视口2次稳定性验证
→ 人工确认脚本
→ 立即或定时回归
→ 结果与证据返回Flowise
```

## 三、双模型API配置

运行一次`PREPARE.cmd`后，用文本编辑器打开：

```text

```

在文件末尾填写：

```dotenv
# 主控LLM：案例理解、结构化、缺口追问、调度解释和限域修复
CONTROL_API_KEY=填写主控模型API Key
CONTROL_BASE_URL=填写主控模型OpenAI兼容API Base
CONTROL_MODEL_NAME=填写接口实际接受的模型标识

# 视觉LLM：Midscene截图理解、视觉作者化和定位恢复
VISION_API_KEY=填写视觉模型API Key
VISION_BASE_URL=填写视觉模型OpenAI兼容API Base
VISION_MODEL_NAME=填写接口实际接受的模型标识
VISION_MODEL_FAMILY=xiaomi-mimo
```

填写规则：

| 配置项 | 要求 |
| --- | --- |
| `CONTROL_API_KEY` | 只填写密钥本身，不加`Bearer ` |
| `CONTROL_BASE_URL` | 可填写以`/v1`结尾的Base，或完整`/chat/completions`地址 |
| `CONTROL_MODEL_NAME` | 必须与接口接受的`model`参数完全一致 |
| `VISION_API_KEY` | 只填写密钥本身，不加`Bearer ` |
| `VISION_BASE_URL` | 可填写以`/v1`结尾的Base，或完整`/chat/completions`地址 |
| `VISION_MODEL_NAME` | 必须是支持图片输入的真实模型标识 |

不要把API Key写入README、Flowise对话、案例文件、银行凭据表单或Git。

## 六、准备被测系统

提交案例前必须确认被测网站已经启动且浏览器可访问。入口可以是本机、办公内网或公网中任意可达的`http`/`https`地址，例如：

```text
http://127.0.0.1:18082/portal/login
```

确认测试账号未锁定、测试数据可安全使用，且不会触发真实资金交易。

首次使用一个入口时，Flowise会展示“目标站点确认”门槛。点击`proceed`后，Harness冻结启动地址、导航来源、交互来源、重定向规则、TLS策略和凭据引用；点击`reject`不会访问该网站。后续Midscene与Playwright只能在冻结档案范围内工作。站点跳转到未确认来源时会失败关闭。

“任意网站入口”表示任意已确认且当前电脑可访问的HTTP/HTTPS网站，并不承诺绕过反自动化、图形验证码、U盾安全窗口或浏览器外原生程序。

### 网页验证策略

页面文字出现“移动证书”“U盾”或“验证码”不会触发验证暂停。验证只允许由案例动作绑定的策略触发：

- `NONE`：例如门户登录与资料一致性案例；不创建验证挑战。
- `AUTO_PERSISTED_UKEY`：只在“转账首次确认”后进入真实`/portal/verification`网页时触发。若已直接到达`/portal/orders/query`则自动通过；若验证页存在已作者化并持久化的网页按钮，Midscene定位后由Playwright点击，并验证单号页面出现。
- `EXTERNAL_CONFIRM_REQUIRED`：仅为明确配置且需要人工操作的网页验证保留。隐藏浏览器不能接管原生Windows U盾/PIN窗口；此类场景会失败关闭并报告当前运行模式不支持人工接管。

同一任务、动作序号与页面指纹最多产生一个验证挑战。验证后必须离开验证页并到达预期页面；未变化会以`I10_VERIFICATION_NOT_RESOLVED`失败，不会重复提示。

以上是当前代码已实现的验证策略。完整审计文档另定义了目标增强链：Midscene 先进行最多三次受控网页尝试，三次耗尽后才打开实时可见浏览器供用户接管，并在恢复后判定验证类型及 Playwright 自动化可行性。该增强链在对应代码、数据库迁移、Flowise 路径和真实运行证据完成前，不得宣称已经落地。

## 七、自然语言案例

用户只需描述业务案例，不需要编写技术提示词。例如：

```text
请创建一个网站登录回归案例。

入口地址是 http://127.0.0.1:18082/portal/login 。从登录页开始，使用本机安全凭据完成账号密码登录。登录成功后检查右上角客户姓名和头像，再进入个人资料页面，验证右上角姓名与个人资料中的客户姓名一致，并确认头像正常显示。

生成并验证Playwright脚本，本次先立即执行。
```

禁止在Flowise对话中输入银行账号和密码。

## 八、安全录入银行凭据

案例没有可用`credentialRef`时，流程会创建凭据会话并返回本机地址：

```text
http://127.0.0.1:18788/v1/i10/credentials/.../form#token=...
```

操作：

1. 在本机浏览器打开该地址。
2. 填写银行测试用户名和密码。
3. 点击“加密保存”。
4. 看到“已安全保存，可关闭此页面”后关闭页面。
5. 回到原Flowise对话，只输入`继续`；系统沿用该对话保存的案例、附件和凭据会话，
   确认凭据引用有效后才会显示本阶段允许的批准操作。

账号密码使用Windows DPAPI加密，只在Worker执行时于内存中解密；不得进入Flowise、模型上下文、普通SQLite业务表、日志、截图、脚本、证据或发布包。

## 九、案例结构与人工确认

主控模型会生成：

- 案例名称和目标。
- 被测系统和入口地址。
- 前置条件。
- 含具体输入语义的操作步骤。
- 与步骤对应的预期结果。
- 最终断言。
- `credentialRef`。
- 图片、文件或视频溯源。
- 验证要求和信息缺口。

缺少必要信息时，Harness 状态卡必须先一次列出缺口，不能直接进入案例
MCP或作者化。摘要完整且确定性校验通过后，页面会展示唯一冻结草案：

- 点击`proceed`：批准页面所示的精确草案并进入作者化。
- 点击`reject`：进入当前旅程的案例修订输入，不直接终止案例。

完整性判断采用三层门槛，避免已经描述清楚的案例被反复追问：

1. 主控模型只判断业务语义是否完整，并输出`COMPLETE`或`NEEDS_CLARIFICATION`及明确缺口。
2. Flowise累计同一旅程中已经确认的描述、URL、图片事实和修订内容；后续只补一个URL时，不会覆盖此前的目标、步骤和预期结果。
3. Harness只保留不可绕过的硬门槛：合法入口URL、有效`credentialRef`、步骤与预期结果合同、来源冲突和人工验证要求。

元素定位、按钮选择器和页面坐标属于Midscene作者化阶段，不是用户必须补充的案例信息。主控模型判定
`COMPLETE`只能放开这类作者化发现项，不能绕过无效URL、无效凭据、合同错误或来源冲突。通过三层门槛后，
系统冻结草案版本、输入修订号和载荷Hash；只有用户在该精确方案上点击`proceed`才进入Midscene作者化。

进入修订输入后，只描述业务内容，例如：

```text
将入口地址改为 http://127.0.0.1:18082/portal/login；把第6步改为“检查右上角姓名和头像”。
```

填写后点击`proceed`只表示提交修订进行校验。校验通过后系统会再次展示完整草案，必须再次点击`proceed`才会写入衡准。

### Flowise回答方式

Flowise不会固定套用“文字—文件—文字”版式，而是按当前状态组合必要模块：

- 简报：始终用简短中文说明当前结果。
- 进度：图片OCR与视觉分析显示当前阶段、真实完成比例、已处理图片数、已用时间、
  最近活动时间、最长等待时间和超时状态；用户点击`proceed`只查询最新状态，不会重复提交任务。
- 成果文件：仅在产生可长期保存的内容时显示，例如案例草案、Playwright源码、
  诊断报告和证据清单。
- 信息补充：仅列出真正缺少的业务信息；账号密码只引导到本机安全凭据页面。
- 输入请求：允许自然语言时给出一个短示例，并明确必填项和禁止内容。
- 人工确认：只显示一个冻结方案及`proceed/reject`的本次效果，不接受自由文本、密码、验证码或PIN。
- 下一步：只保留当前需要用户完成的一项操作。

默认对话不展开JSON、MCP参数、内部状态枚举和完整技术日志。需要技术排查时，
使用可下载的`.txt`、`.md`或`.json`文件承载细节。

Flowise在同一个回复气泡中追加新的阶段结果时，系统默认只展开最新一段；较早内容通过
“查看本轮较早输出”按钮按需展开。该功能只折叠显示，不删除历史记录或验收证据。

案例草案通过校验后通常返回两个文件：

- `案例草案.md`：供用户阅读和确认。
- `案例草案.json`：供后续自动化处理和问题追踪。

下载链接由本机Harness签发，有效期短且只能使用一次。重新获取状态时会签发新链接，
旧链接随即失效。Flowise原生附件可作为界面增强，但不作为权威交付渠道。

## 十、文件、视频和图片输入

### 如何添加附件

在Flowise聊天页可使用三种等价方式：

1. 点击输入框左侧回形针并选择本地文件。
2. 将本地文件拖到聊天输入区域。
3. 在剪贴板中复制图片后，将光标放入聊天输入框并粘贴。

附件出现缩略图或文件名后，再输入案例说明并发送；发送前可点击附件上的删除按钮移除。
Windows截图工具和其他只把图片放入剪贴板项目（而非文件列表）的程序同样受支持；成功识别后，
输入区会显示“已从剪贴板添加图片附件”。若浏览器、远程桌面或安全软件阻止读取剪贴板，
请改用回形针上传，不要反复提交同一任务。
系统只接受本节列出的受控类型，一次最多16个附件。附件进入Flowise管理的存储后，工作流只使用
带作用域的文件引用，不把本机绝对路径作为案例参数。若类型不受支持，页面会显示红色提示且不会提交。

### 案例文件

支持：

- `.xlsx`
- `.csv`
- `.docx`
- `.json`

上传后输入：

```text
请导入附件中的自动化测试案例，检查字段完整性，并将确认后的案例生成可执行回归脚本。
```

系统会执行字段映射、错误报告和人工纠正。不接受旧式`.xls`、宏工作簿、宏文档和危险压缩结构。

### 成功操作视频

首版要求：

- MP4/H.264。
- 单浏览器窗口。
- 不超过1080p、15分钟和500 MiB。
- 画面显示鼠标指针。

上传后输入：

```text
请分析附件中的成功操作录屏，提取操作步骤、输入内容、预期结果和验证要求，生成回归案例。
```

系统通过FFmpeg抽帧、本机PP-OCRv5 ONNX中英文识别、确定性文字变化时间线和主控事实筛选生成草案。视频导入不调用视觉模型，也不声称仅凭OCR看见了鼠标点击；所有推导动作必须逐项确认。

### OCR进度与超时判断

图片或视频进入分析后，Flowise会显示：

- `QUEUED`：任务已入队；
- `OCR_STARTING`：Worker已领取任务并准备OCR；
- `OCR_AND_REDACTION`：正在执行OCR和脱敏，比例按真实已处理图片数计算；
- `VISION_AND_FACT_SELECTION`：正在进行视觉理解和案例事实筛选；
- `WAITING_USER_REVIEW`：分析完成，等待人工确认；
- `FAILED`或`TIMED_OUT`：失败关闭或租约超时，不会冒充成功。

等待页面同时显示已用时间、最近活动间隔、最长等待时间和租约截止时间。任务处理中点击
`proceed`只刷新状态；不要重新上传相同附件。超过等待上限或显示`TIMED_OUT`时，按页面给出的
错误码处理或重新发起新任务。

### 支持图片

自然语言、文件和视频入口均可附带`.png`、`.jpg/.jpeg`、`.webp`或`.bmp`图片。图片可承载页面、
测试数据、输入内容、预期结果和验证提示。系统执行中英文OCR并由主控模型筛选案例事实，进入正式案例前
必须人工确认。不要上传包含明文密码、API Key或无关个人信息的图片。

## 十一、Midscene作者化与人工验证

批准案例后：

1. Harness生成上、中、下三层动作上下文。
2. Midscene调用视觉模型观察页面并输出元素定位建议。
3. Playwright把定位建议转换为受控 DOM 定位器，再执行页面操作并验证结果。
4. 保存脱敏ActionTrace和定位依据。
5. Playwright补充URL、DOM、可访问性和网络事实。

作者化期间不要同时操作随包Chromium。

遇到以下验证时必须暂停并通知用户：

- 短信OTP。
- TOTP。
- 图形验证码。
- 扫码。
- U盾。
- 移动证书。
- 生物识别。
- 人工审批。

验证码、U盾PIN、私钥、物理按键和安全桌面操作必须由用户本人完成。完成验证后回到Flowise：

- 点击`proceed`：表示“我已在被测页面完成当前验证，可以恢复浏览器任务”。
- 点击`reject`：中止本次执行并失败关闭。

不得把验证码、PIN或私钥输入Flowise反馈框。

## 十二、Playwright源码与稳定性验证

ActionTrace完成后：

1. 确定性Builder生成`.cjs`源码。
2. 使用纯Playwright独立验证。
3. 进入`I10_2X2_V1`稳定性规则。
4. 使用2个视口，每个视口执行2次，共4次。
5. 四次全部成功后才签发证书。

任意一次失败都不能签发正式证书。成功后Flowise返回脚本版本、SHA-256、验证摘要和完整源码下载入口。下载源码Hash、实际执行Hash和证书Hash必须一致。

## 十三、执行方式

### 立即执行

```text
立即执行这个已验证的回归案例。
```

对应`ON_DEMAND`。

### 单次定时

```text
请在2026年7月25日上午10点，按照Asia/Shanghai时区执行一次。
```

对应`ONE_TIME`。提交前确认执行时间、时区、目标脚本、错过执行策略和重试次数。

### 周期执行

```text
请从下周开始，每个工作日上午9点执行一次，时区为Asia/Shanghai。
```

对应`RECURRING`。提交前确认Cron、时区、执行频率和目标脚本。

执行方式采用两步交互：

1. 在允许输入的节点填写“立即执行”、单次时间或周期规则，再点击`proceed`。这一步只解析和校验当前Human Input反馈，不创建任务或调度。
2. 系统展示规范化后的唯一计划、时区和时间/Cron。核对无误后点击`proceed`才创建任务或调度；点击`reject`则不创建并保留当前已验证脚本。

空白计划、模糊时间、缺少时区或非法Cron不会进入最终确认，更不会调用运行/调度MCP。修复版调度使用同一流程，且只读取当前输入，不读取旧对话消息。

## 十四、结果与证据

执行完成后，Flowise先返回简报，再按实际成果提供必要文件和下一步。可下载内容包括：

- 任务状态。
- 开始和结束时间。
- 脚本版本与Hash。
- 断言结果。
- 证据摘要。
- 截图或制品元数据。
- 失败分类和安全错误摘要。

完整二进制证据和源码通过受控下载入口交付，不在聊天框中截断拼接，也不把原始MCP
结果直接显示给用户。用户不需要阅读内部参数即可知道结果、下载成果并选择下一步。

## 十五、失败后的反向修复

回归失败时：

1. Harness自动分类失败。
2. 页面只保留一次“是否生成并验证修复候选”的确认。
3. 只向主控模型提供当前步骤的有限修复上下文。
4. 主控模型只能修改当前候选脚本，不能修改项目源码。
5. Builder重新规范化候选。
6. 重新运行纯Playwright验证。
7. 重新执行4次稳定性验证。
8. 用户通过`proceed/reject`确认是否激活精确Hash的修复脚本。
9. 激活后再独立确认是否复跑；如需调度，重新输入并确认时间计划。

未经验证或未经用户确认的修复脚本不得激活。

## 十六、进度、恢复与窗口关闭

`VERIFY.cmd`、`PREPARE.cmd`、`START.cmd`和`STOP.cmd`显示真实进度、阶段、已用时间、最近活动和等待上限。不可量化阶段仅显示心跳，不显示虚假百分比。

发生Ctrl+C、断电、网络或模型暂时失败后，再次运行同一CMD会验证断点并安全续跑。强制从头执行：

```cmd
VERIFY.cmd --restart
PREPARE.cmd --restart
START.cmd --restart
STOP.cmd --restart
```

成功后CMD默认等待按任意键关闭。自动化调用：

```cmd
VERIFY.cmd --no-pause
PREPARE.cmd --no-pause
START.cmd --no-pause
STATUS.cmd --no-pause
STOP.cmd --no-pause
```

也可先设置：

```cmd
set HENGZHUN_NONINTERACTIVE=1
```

失败和取消不会进入成功等待，并保留原错误码或退出码130。

## 十七、安全停止

完成测试后：

1. 保存需要的脚本和证据摘要。
2. 关闭测试浏览器窗口。
3. 运行`STOP.cmd`。
4. 等待Flowise、Worker、MCP、Harness依次停止。
5. 运行`STATUS.cmd`确认全部停止。

STOP只终止本包拥有的进程，不终止未知进程。运行数据保存在`.data`，正常重启后继续存在。

## 十八、常见问题

### START只启动了四项服务，但最终失败

说明模型探针或Agentflow发布没有通过。根据错误码检查`.data\runtime.env`中的Base、模型标识、API Key和服务商可用性；修复后重新运行`START.cmd`续跑。

### 视觉模型超时

先确认`/models`鉴权和模型可见性，再确认该模型真实支持图片输入及推理服务正常。不得以Playwright或Mock替代视觉探针。

### 被测银行页面打不开

衡准不会自动启动目录外的被测系统。先启动复兴银行，再提交回归任务。

### 页面要求验证码或U盾

系统应暂停并请求人工操作。无人值守计划包含人工验证时必须失败关闭或等待人工介入。

### STATUS显示端口被未知进程占用

不要强制结束未知进程。先确认端口所有权，再关闭冲突程序或调整受控配置。
