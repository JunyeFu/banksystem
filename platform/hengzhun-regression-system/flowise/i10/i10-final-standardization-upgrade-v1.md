# I10 最终标准化升级与可重跑验收

状态：实施中  
权威范围：当前桌面 I10 导出包；v6 为可回退历史，v7 为本轮目标实现。  
完成口径：本文件的代码、测试、发布和运行验收均须同时具备；历史 PASS 不可替代当前证据。

## 1. 当前事实与缺口

- v7 已由唯一构建器生成，但尚未经公共 API 发布；v6 仅保留为可回退历史。账本中的 13 条 PASS 均绑定旧部署图 Hash，已降级为 `HISTORICAL_STALE`，必须在 v7 发布后重跑。
- 当前真实候选 ID 使用 `candidate_<40 hex>`，而部分跨会话路由仍按 UUID 长度识别，导致“候选已生成却被判定不存在”。
- H1 图片链已证明候选和 2x2 证书可生成，但未完成激活、正式执行和结果收件箱。H2/H3、三种 U 盾分支和反向修复链没有当前版本端到端证据。
- 现有验收 `recover` 只能补写临近终态，不能从任意中途阶段继续；部分运行目录缺失确定的终态结果文件。
- 受控转账的金额、用途仍有兼容性文本抽取，必须迁入冻结草案的类型化业务输入。

### 1.2 案例目录与正反向覆盖矩阵

| 类别 | 案例 | 文本与图片共同业务目标 | 正向特有门槛 | 反向必须注入/复验 |
|---|---|---|---|---|
| 轻度 | L1 | 登录后主页与个人资料的姓名、头像一致。 | `NONE` 验证策略；只读比对。 | 登录定位器变化、头像区域不可见、结果收件箱丢失。 |
| 轻度 | L2 | 查询账户并核对余额、状态。 | 账户读模型与只读区域定位。 | 空列表、状态文本变化、OCR 添加无关金额。 |
| 轻度 | L3 | 查询消息并确认未读摘要。 | 幂等场景夹具提供通知。 | 无通知、筛选文本变化、重复执行不得重复造通知。 |
| 中度 | M1 | 筛选交易并核对结果状态。 | 类型化筛选条件与日期范围。 | 空交易、日期边界、筛选控件定位失败。 |
| 中度 | M2 | 查询收款人并核对掩码账号、状态。 | 受控收款人夹具与敏感显示脱敏。 | 无收款人、掩码格式变化、OCR 不能暴露完整账号。 |
| 中度 | M3 | 查询文档并核对标题、日期、下载入口。 | 只验证入口，不下载不受控文件。 | 空文档、日期格式变化、下载控件不可见。 |
| 高度 | H1 | 提交转账并确认首次确认后的路由。 | 冻结的收款人、金额、用途；`AUTO_PERSISTED_UKEY`。 | 结果未知时不能重放首次确认；应读取受理/单号对账。 |
| 高度 | H2 | 网页 U 盾验证或直达单号页的可选分支。 | 三次独立观察；Midscene 仅定位、Playwright 仅点击。 | 三次无效观察后才 handoff；不可操作 PIN/OTP/原生窗口。 |
| 高度 | H3 | 单号页核对收款人、金额与受理状态。 | H1/H2 的业务回执关联。 | 单号缺失、金额/收款人不一致、挑战后页面未变化。 |

每行均须运行 `TEXT_ONLY` 与 `TEXT_WITH_IMAGE` 两个变体；图片变体只能以 OCR 事实补充页面标签、数值或状态，不能改变案例意图、目标 URL、类型化转账输入或验证策略。

## 2. 固定架构合同

1. `OpaqueReferenceV1` 统一 Journey、Preparation、Candidate、Certificate、Task、Run、Schedule 的格式；所有服务、Flowise 构建器和验收驱动只能复用该注册表。
2. `ReleaseIdentityV1` 固定 Flow ID、版本、规范化图 Hash、Harness/Worker 代码版本、迁移版本与案例目录版本。账本只统计与当前身份完全相同的记录。
3. `JourneyTransitionV2` 只包含一个明确下一动作及其冻结载荷、版本、Hash、引用和恢复动作。冻结案例、作者化、候选编译、候选激活、调度、修复均为不同动作类型。
4. `TypedBusinessInputsV1` 保存非敏感业务输入及来源；凭据始终仅为 `credentialRef`。Builder 只消费类型化字段，旧文本抽取仅用于旧草案兼容和警告。
5. `AcceptanceCheckpointV1` 与 `AcceptanceRecordV3` 使用原子写入，分别保存中断位置与终态证据；每次运行都生成 `run-result.json`。

## 3. 实施顺序

### S1：合同、证据与账本基础

- 新增统一编号注册表、发布身份计算器、案例目录和验收账本 v3。
- 将旧账本记录标记为 `HISTORICAL_STALE`，保留只读历史证据但不参与完成数。
- 为每个 L/M/H 文本和图片路径建立同一案例目录：夹具版本、自然语言、必要类型化输入、截图规则、OCR 语义合同、验证策略和调度模式只在一处定义。
- 将现有 `candidate_<40 hex>`、`certificate_<40 hex>`、`script_<40 hex>` 等事实格式写入机器可读注册表；禁止 Flowise、Harness、Worker、验收驱动各自写正则。
- `AcceptanceRecordV3` 以 `releaseIdentity + caseId + variant + attempt` 作唯一键，写入前生成 checkpoint，终态必须写入 `run-result.json`。缺少任何一个终态引用的记录只能是 `INTERRUPTED` 或 `FAILED`，不能是 `PASSED`。

### S2：Harness 与 Agentflow v7

- 新建 v7 构建器和图，v6 不覆盖；PREPARE、START、发布、静态验证和清单改为 v7 单一入口。
- 每次 Flowise 执行最多做一次状态写入；写入后结束本次执行，下一轮从 JourneyTransitionV2 读取状态。
- 删除旧的工具串联和重复恢复分支；所有跨会话恢复由 Harness 的权威引用决定，不能靠聊天文本或正则猜测。
- 使用动作特定的确认提示；聊天仅输出简报、唯一下一步和成果链接，原始 MCP 数据写入 Artifact。
- 所有恢复入口只读取 `JourneyTransitionV2` 的冻结引用；不得由“继续”、消息历史、候选名称正则或旧 Flowise 状态推测下一阶段。
- 发布身份使用同一规范化函数计算源图、公共 API 回读图和清单三方 Hash；三个值不一致时 START/STATUS 必须报告“不具备业务就绪”，而不是只显示 HTTP 健康。

### S3：作者化、验证与副作用恢复

- 登录、账户、消息案例固定 `NONE`，不得从页面静态文字产生验证挑战。
- H1 验证首次确认后路由；H2 实现单号页跳过、网页验证三次独立观察/定位/Playwright 点击、三次失败才转可见接管；H3 校验单号、收款人、金额和状态。
- 为每一次观察写入不可变验证尝试；成功必须具备路由、DOM 和业务证据。
- 为首次确认等副作用动作写入接收回执。中断后进入 `OUTCOME_UNKNOWN`，只读对账成功前不得重放点击。
- 完成失败分类、候选修订、纯 Playwright、2x2、用户确认、激活、复跑的反向闭环。
- `TypedBusinessInputsV1` 至少定义 `payeeRef`、`amount`、`currency`、`purpose`、`dateRange`、`filter` 和 `verificationPolicy`；所有字段都带 `source`、`schemaVersion`、冻结 Hash。H1-H3 缺任一必要字段时在案例补充阶段失败关闭，Builder 不再从自然语言回猜。

### S4：可恢复验收执行器

- 每个 Flowise 请求后写入断点；恢复从现有 Journey/Preparation/Job/Candidate/Certificate/Task/Schedule/Inbox 继续。
- 同一案例变体使用独占锁和幂等键；重复执行不能覆盖证据或重复创建交易、任务、调度。
- 旧/不同 ReleaseIdentity 的记录自动失效；运行失败也写入失败阶段、可恢复性和安全诊断。
- `recover` 必须按实际资源状态恢复：Journey → Preparation → Build Job → Candidate → Certificate → Decision → Task/Schedule → Inbox。只补写账本而没有对应实时资源和终态 Artifact 的恢复为失败关闭。
- 每个具有副作用的步骤（首次确认、激活、创建调度）都记录请求幂等键、接收回执和可对账业务标识；响应丢失标记 `OUTCOME_UNKNOWN`，先对账后决定继续/失败，不得盲重放。

### S5：验证与当前版本实证

- 自动化覆盖编号格式、图路径、变量来源、每阶段重复执行、进程/模型/Worker 中断、响应丢失、U 盾三分支、账本失效、反向修复和敏感信息扫描。
- 发布 v7 后回读 Flow ID、节点/边、规范化 Hash 和 `deployed=true`；重启当前四个受管服务。
- 依次执行 L1-L3、H1-H3、M1-M3 的文本和图片链，共 18 条；每条必须产生候选、2x2、激活决定、执行/调度、收件箱和终态 Artifact。
- 周期调度验收后停用；额外注入一次定位器故障完成反向修复链。
- 完整运行顺序固定为：L1–L3 → M1–M3 → H1–H3；每例先执行场景夹具/API 预检，文本变体先于图片变体。任意失败先进入问题登记与同版本修复验证，禁止通过替换端口、账号或旧证据把失败“绕过”。

## 4. 重放不变量

| 阶段 | 可恢复事实 | 禁止行为 |
|---|---|---|
| 草案 | 冻结草案、版本和 Hash | 重新请求主控模型或丢失 OCR 事实 |
| 作者化 | Preparation 与 Build Job | 重复提交作者化 |
| 候选 | 40 位 Candidate ID 与状态 | 因路由误判退回案例确认 |
| 证书 | 4 个唯一验证记录 | 缺失记录仍签发证书 |
| 激活 | Candidate/Certificate/Hash 一致 | 重复激活或激活未持证脚本 |
| 正式执行 | Task/副作用回执 | 结果未知时重放确认点击 |
| 调度 | Schedule 与租约 | 回复丢失时创建第二个调度 |
| 修复 | Patch/证书/决定 | 自动激活或覆盖原脚本 |

## 5. 统一失败分类与防重跑规则

| 类别 | 例子 | 系统处理 | 重跑前置条件 |
|---|---|---|---|
| 输入未完成 | URL、credentialRef、H 链类型化金额/用途缺失。 | 停在 Journey 补充/凭据状态；不提交 TargetProfile 或作者化。 | 冻结草案版本递增且缺口清零。 |
| 模型/传输暂断 | 控制模型或视觉模型超时、Flowise 会话中断。 | 保存 checkpoint，显示可恢复动作；不复制写入。 | 当前发布身份与输入 Hash 不变，恢复同一 Journey。 |
| 定位/页面变化 | Midscene 无定位证据、Playwright DOM 不匹配。 | 写入诊断 Artifact、创建修复候选；不激活。 | 新候选须纯 Playwright + 2×2 + 用户决定。 |
| 业务副作用未知 | 首次确认或调度创建后响应中断。 | `OUTCOME_UNKNOWN`，只读查询对账。 | 已证明未生效才可使用同一幂等键重试。 |
| 验证未解决 | U 盾验证页三次观察后仍未发生预期页面变化。 | 进入可见接管或明确失败；不循环 Human Input。 | 页面指纹变化且 route/DOM/business 三类证据复核。 |
| 发布/环境漂移 | Flow Hash、迁移、Worker 版本或夹具端口改变。 | 当前账本记录失效；停止接收完成计数。 | 重启到匹配 ReleaseIdentity 后从 checkpoint 重跑。 |

## 6. 交付前的执行顺序与硬门槛

1. **先完成 S1/S2**：统一引用、ReleaseIdentity、账本 v3、v7 唯一生成/发布链，之后才允许重跑任何案例。
2. **再完成 S3/S4**：类型化转账输入、副作用对账、三次 U 盾观察、反向修复和真实恢复。每项先有定向测试，再有单例运行证据。
3. **最后执行 S5**：18 条链在同一 ReleaseIdentity 下逐条完成，周期计划验收后停用，反向注入只执行一次且保留原脚本。
4. 每次正式验收前执行：Agentflow 静态验证、Journey/验证策略测试、当前运行版本检查、场景夹具预检；每次终态后写入可重读 Artifact 和账本 v3。
5. 若代码或流程图任何一项再改变，所有受影响的记录自动变为 `HISTORICAL_STALE`；不得“只补一条结果”继续宣称全量通过。

## 7. 最终门槛

仅当所有 18 条记录绑定同一 ReleaseIdentity，且文本/图片语义匹配、OCR 不改变业务意图、三种调度、U 盾三分支及反向修复均具备当前运行证据后，才允许依次写入：

```text
I10_BROWSER_OCR_CASE_SUITE_ACCEPTED
I10_FLOWISE_18_CHAIN_ACCEPTED
I10_PORTABLE_FOLDER_VERIFIED
I10_FLOWISE_LOCAL_ACCEPTED
```
